## Scope

Port the Java row-set unit tests that exercise behavior exposed by `oxhaven_contracts::rowset::RowSet`, as Rust tests in `oxhaven-rowset`. Skip tests of Java-only internals (RSP containers, sorted-ranges layout, reference counting, serialization) and list each skipped test class with its reason in Notes. A test that fails against the contract implementation is a finding: record it, do not edit the contracts crate.

## Gate

```bash
cargo test -p oxhaven-rowset
```

## Notes

Ported tests are in `crates/oxhaven-rowset/tests/rowset.rs`; each names the Java test it ports.
Sizes of the randomized tests are smaller than in Java because the contract row set costs
O(ranges) per operation; each test states what it runs. Expected values come from a sorted-key
model, not from `java.util.Random` sequences.

### Finding: `RowSet::sub_set_by_key_range` panics when `last` is negative

`WritableRowSetImplTest#testRangeByKey` asks for key ranges that start two below the first key.
For a row set whose first key is 0 or 1 that includes `subSetByKeyRange(-2, -2)` and
`subSetByKeyRange(-2, -1)`, and Java returns the empty set. The contract method clamps `first`
to 0 and then builds `RowSet::from_range(0, last)`, which panics with
`invalid row range 0..=-2` (and `0..=-1`). `rows.sub_set_by_key_range(-2, 1)` works. The
committed port (`sub_set_by_key_range_for_every_first_and_last`) covers every pair with
`last >= 0`; the pairs with `last < 0` are left out until the contract returns the empty set
for them.

### Differences in the contract shift type, seen while porting (no Java test fails on them)

- `RowSetShiftData::apply` returns `ShiftError::Collision` when a moved key lands on a key that
  did not move. Java's `RowSetShiftData#apply(WritableRowSet)` removes the source ranges and
  inserts the moved keys with no such check, so the two keys become one.
- `RowSetShiftData::new` returns `ShiftError::BadRange` for a range with `last < first`.
  Java's `Builder#shiftRange` ignores such a range. `oxhaven_rowset::ShiftBuilder` ignores it
  too, before calling `new`.

### Java tests not ported

`WritableRowSetImplTest`:

- `testSerialize`, `testSerializeRandom`, `testSerializeRandomSize`: Java serialization.
- `testSimpleOpsRefCounts`, `testConversionRemovalRefCount0`, `testRetainRefCountRegress`,
  `testRetainRangeRefCountRegress`, `testReleaseReleasedRegression0case*`: reference counting.
- `testChunkInsertAndRemove`, `testFillChunk`, `testAsKeyRangesChunk`: chunk API, over a list
  of internal container layouts.
- `testIteratorBinarySearch`, `testIteratorBinarySearchForSingleRangeIndex`,
  `testRangeIteratorAdvance`, `testRangeIteratorAdvanceEmptyIndex`,
  `testRangeIteratorAdvanceBack`, `testSimpleIteratorForEach`, `testSearchIteratorRegression0`,
  `testSearchIteratorBinarySearchFirstCallNotFoundNoNext`, `testReverseIteratorAdvanceRegression0`
  to `6`, `testIteratorAdvanceRegression1`: search, reverse and range iterators with `advance`
  and `binarySearchValue`; the contract has only `iter` and `ranges`.
- `testGetRowSequenceByKeyRange`, `testGetRowSequenceByPosition`,
  `testGetAverageRunLengthEstimate`: `RowSequence` API, not in the contract.
- `testInvertWithMax`: `RowSet#invert(keys, maximumPosition)` is not in the contract.
- `testUnionIntoFullLeaf`, `testFunnyOverLap`, `testSplitRangeIterator`, `testAddIndex`,
  `testAddIndex2` to `5`: they assert only `validate()` and reference counts of the internal
  tree, mostly on long literal inputs. Union and builder results are covered by the model
  tests.
- `testSubsetOfRegression0`, `testIntersectRegression0`, `testRemoveRegression0`,
  `testMinusRegression2`, `testRemoveSrFromRspFullBlockRegression`,
  `testRemoveSrFromRspFullBlockRegression2`, `testInsertWithSrTypeChange`: regressions of one
  internal representation (sorted ranges) against the other (RSP) on literal data; there is one
  representation here. `testMinusRegression0`, `testMinusRegression1`, `testRemoveRegression1`
  and `testRemoveRegression2`, which are short, are ported.
- `testSequentialBuilderCompactness`, `testSequentialBuilderMakesSortedRanges`,
  `testSequentialBuilderMakesSparseSortedRangesLong`, `...Int`,
  `testSequentialBuilderMakesDenseSortedRangesInt`: internal layout chosen by the builder.

- `testOverlappingRanges` and `testRandomBuilder` are ported for their results; their checks
  of the internal `RangePriorityQueueBuilder` and of a search iterator are not.
