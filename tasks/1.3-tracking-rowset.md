## Scope

A tracking row set that keeps the previous cycle's value: `prev()` returns the row set as of the end of the last cycle and is refreshed at most once per clock step, on first mutation in that step. Sequential and random builders. Port the shift tests for `RowSetShiftData` (apply, unapply, intersect, builder) against the contract type.

## Notes

- `TrackingRowSet` (`src/tracking.rs`) takes the clock step as a `u64` argument to `prev(step)`
  and `write(step)`. As in Java, only the step number matters: a write made while the graph is
  idle belongs to the step of the last cycle. Reads never mutate, so no lock is needed inside;
  the owner wraps it as it needs. The `TrackingRowSet.Indexer` slot (data index) is not part of
  it.
- `RowSetBuilderSequential` panics on an out-of-order append, where Java throws with the default
  `sequentialBuilderCheck`. `union_all` is `RowSetFactory#unionInsert`.
- Shift helpers (`src/shift.rs`): `for_each_shift` and `for_each_unshift` (the memmove-safe
  callback orders), `intersect`, `ShiftBuilder`, `CoalescingShiftBuilder`. Moving a row set back
  to pre-shift keys is `data.inverse().apply(rows)` on the contract type.
- `ShiftBuilder` reports overlapping or crossing ranges from `build`, not from `shift_range`.
  `Builder#appendShiftData`, `#limitPreviousShiftFor` and `#getMinimumValidBeginForNextDelta`
  are not ported; they serve `merge` and have no test in `RowSetShiftDataTest`.
- `CoalescingShiftBuilder` sorts its input, so it accepts ranges in any order. Java's
  `SmartCoalescingBuilder` requires apply-iterator order and throws on some violations. The
  result is the same set of moves for the pre-shift keys; the Java tests compare exactly that.
- The memmove tests of `RowSetShiftDataTest` do not depend on the callback order: their
  neighbouring shifts have equal deltas and merge into one range per run. `tests/shift.rs` adds
  a test with unequal deltas whose expected order is read from
  `RowSetShiftData#apply(RowKeyRangeShiftCallback)` and `#unapply`.
- `RowSetShiftData#intersect` and `#unapply(WritableRowSet)` have no Java test; theirs are
  written from the source.
- Not ported: `RowSetShiftData#forAllInRowSet`, `#applyIterator`,
  `#extractParallelShiftedRowsFromPostShiftRowSet`, `#getEffectiveSize`, `#unapply(rowSet, offset)`,
  `#applyShift`, `#unapplyShift`. Nothing calls them yet, so no `unported!` was added.
- Differences in the contract shift type are listed in the notes of task 1.2.
