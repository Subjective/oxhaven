## Scope

Implement `UpdateGraph`: the logical clock, source refresh, and a notification queue that runs a notification only when `can_execute` is true, so a node with several parents runs once after all of them. Provide the merged-listener building block (recorders plus one merged notification). Single-threaded and deterministic first; `run_cycle` is the only way a cycle advances. No periodic timer in this task.

## Notes

- `graph::SteppedUpdateGraph` implements `UpdateGraph`. Building blocks: `graph::Subscribers`
  (the listener side of a table), `graph::ParentListener` (one parent), `graph::MergedListener`
  (several parents).
- Every refreshing table must answer `Dependency::satisfied` through `Subscribers::satisfied`:
  after a table notifies, it is satisfied only once its deliveries have run. The listener
  contract gives a listener no way to learn that a delivery to it is queued, so this is what
  keeps a merged listener from running before its recorders. See the doc comment on
  `Subscribers`.
- A failure raised after the result already notified on the step is delivered at the start of
  the next cycle.
- The clock follows the contract (the step increases when a cycle starts); Java increases it
  when the cycle ends.
- Not built: terminal notifications, the periodic timer, performance entries.
