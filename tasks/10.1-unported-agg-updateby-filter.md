  the component type of a vector or an array.

## Owner questions

1. Search of an `Instant` column for a date (`2024-01-01 UTC`) or a time of day (`10:30`)
   (S2, S3). Java adds a day in `DateTimeUtils.timeZone()`, the JVM's default zone, and
   reads a time of day as today in that zone. The engine has no server time zone (the
   CSV writer reads the machine's, `docs/CSV.md`). Should the engine take the machine's
   zone and serve zones with one offset, refusing others? The time-of-day case depends
   on the date the request runs: is it an A15 refusal?
2. Orderings Java fails with `ClassCastException` only when two values meet, and then
   depending on object identity (A1, A3, A4, A8): min/max/median of a `ZoneId` column, of
   an array column, of a vector of vectors or of periods; sorted first/last by a period
   of a refreshing parent. `PeriodGuard` reproduces one such case for `Period`; whether
   two equal `ZoneId`s are one object in Java is not knowable from the request. Refuse
   all of these as A15, or reproduce them like `PeriodGuard`?
3. Results whose column Java makes without a component type, which a client receives as
   a list of strings (A2, A13, U6): min/max/median/unique of a vector of Booleans or
   Instants, a formula aggregation or rolling formula whose result is a vector of
   objects. Reproduce the strings, or allow the typed result as A14 does?
4. Formula results Java computes from the wrong input (A12, A14-A16, U8, U10-U12): `i`,
   `ii`, `k` as the group's position or 0, a formula moved to the shared group operator
   reading that operator's output, `K = K + 1` by `K` giving nulls, the first bucket
   column's value given for another, row variables of a chunk's table. These look like
   defects: refuse as A15?

## Handover

Context ran short after A6, A7 and A9. Remaining items Deephaven serves with a defined
result, with what is known:

- S1 (search of vector and array columns): Java wraps the element filter (`MatchFilter`,
  a range filter or the string pattern; all expose a chunk filter) in
  `VectorComponentFilterWrapper`, keeping a row if any element passes. A null vector
  reaches `vector.iterator()` unchecked (`IntVectorChunkFilter` and the others), so a
  null cell throws `NullPointerException`. Needs an "any element" `Resolved` variant and
  its evaluation in `filters.rs`, after task 9.10 merges.
- U16 (`update_by` over vector or array columns): needs a `Values` variant of lists;
  Java buckets and forward fills them as objects. An array is hashed by identity in Java
  (`Object#hashCode`), so bucketing by an array column is likely an owner question;
  vectors compare by content.
- C2 (`DecimalFormat#format` from 2^53 up and at exact halves): `DigitList#set(double)`
  takes the digits of `FloatingDecimal.BinaryToASCIIBuffer#dtoa`, which for an integer
  below 2^63 gives all its exact digits and above that is not always the shortest; needs
  a port of that algorithm.
- L7 (`BigDecimal`/`BigInteger` match literals): `MatchFilter` parses with
  `new BigDecimal(str)`; `BigDecimal#equals` is scale-sensitive. Needs a `Key` in
  `filters.rs`.
- A5 (distinct of a vector column), U7/U9 (rolling formula over a vector column),
  A11/U15 (count where over a vector column): need vectors of vectors or filters over
  vectors.
- U1-U5 (index, `get`, `subVector`, `diff`, `len` in a rolling formula): Java's ring
  buffer wrappers throw `NoSuchElementException` outside the window, where a vector
  column gives null; needs the evaluator to report an out-of-range read.
- L1, L2, L3, C1: `String#equalsIgnoreCase` for supplementary characters (JDK 21 compares
  code points through `Character#toUpperCase(int)`), Unicode `Nd` digits in
  `Integer#parseInt`, hexadecimal float literals, `Double#toString` of a subnormal with
  one digit; each needs a table or algorithm the workspace does not have.
