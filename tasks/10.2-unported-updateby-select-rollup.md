### Done

- U1, U2, U3, U4 (`[]`, `get`, `subVector`, `diff` of a rolling window): `update_by/window.rs`
  finds every read by position when the formula is compiled and, before the formula is
  evaluated, evaluates each one's position over the rows that reach it (the side of
  `?:`, `&&`, `||` that Java evaluates). A window's `get` reads `front((int) index)`: a
  position outside the window fails the table with `java.util.NoSuchElementException`,
  a null `long` position reads element 0, and so does 2^32 (the formula is handed the
  truncated position). A slice (`IntVectorSlice`) reads through `get` with
  `Vector#clampIndex`, so a position outside the window fails; its iterator gives nulls,
  so `sum` and the like of a slice that reaches outside are served. `diff(stride, w)`
  fails for a stride other than 0 over a window that is not empty. `first` and `last`
  of a slice fail where their position is outside the window; `nth`, `countDistinct`,
  `distinct` and `rank` are handled the same way, but the expression crate refuses them
  with a vector argument today, so that code is not reached by any test.
  `w_[i]` of the token's `__PARAM_COLUMN__` (the parser reads it as a column array) is
  an index too.
- U5 (`len` of an expression): served when the expression reads no window of objects.

### Still `unported!` in group 1

- A slice of a window as the formula's result (`x.subVector(0, 1)`): Java copies a result
  that is the window itself (`BaseRollingFormulaOperator#getChunkSetter`) but stores a
  slice as it is, which reads the ring buffer as it is when the result is read: the
  recorded Java result is `[0]` or `[65]` for every row. Owner question 5.
- `get`, `[]`, `subVector` or a reading function of a window chosen by `?:` or a cast
  (`(c ? x : y)[0]`), which this pass does not follow; `binSearchIndex` of a slice.
- `len` of an expression that reads a window of objects (U5 for objects).

## Owner questions

   stores the slice, which keeps reading the window's ring buffer, so every row shows
   what the buffer holds when the result is read (recorded: `[0]` or `[65]` for every
   row). Refuse as A15 (recommended), or serve the slice's values at the time of the row?

   shifted column whose name a table column already has, and a static `select` with new
   row keys that reads parent columns or `i`, `ii`, `k` by those keys. Refuse as A15
   (recommended)?
