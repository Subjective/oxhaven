## Notes

Every Java answer below was observed on Deephaven 42.9 (the oracle's embedded server,
Python console scripts through `pydeephaven`, vectors made by `group_by`, arrays by
`new int[]{...}`) as well as read in the source. Java buckets `update_by` with
`partitionedAggBy` (`BucketedPartitionedUpdateByManager`), which hashes and compares a key
of objects with `ObjectComparisons#hashCode` and `#eq`, that is the objects' own
`hashCode` and `equals`.

### Done

- Bucketing by a vector column whose elements, at every depth, are integers, `char`s,
  `Boolean`s, `String`s, `Instant`s or vectors of these: equal vectors are one bucket (one
  size, equal elements, a null element equal only to a null element), null vectors are one
  bucket, an empty vector is its own. Every vector class compares and hashes these
  elements by value (`IntVector#equals`, `IntVectorDirect#equals` with `Arrays#equals`,
  `ObjectVector#equals` with `Objects#deepEquals`), so the answer does not depend on where
  the vectors came from. The key is built from the Arrow list in bulk, its element type
  resolved once per chunk (`values.rs` `push_list_keys`); the scalar key paths are
  unchanged.
- Bucketing by an array column is Java's error, from `ChunkedOperatorAggregationHelper
  #aggregation`: `Cannot aggregate using an array column: A, column type is an array of
  int` (`class java.lang.String` for a `String[]`), after every other check of the request.
- Forward fill, rolling count and rolling group of a vector or array column (Java's
  `ObjectFillByOperator`, `ObjectRollingCountOperator`, `RollingGroupOperator`): only
  which cells are null matters; the cells are carried as they are.
- `(c ? x : y)[i]` and `.get(i)` of a condition between windows of one type (nested
  conditions too) in a rolling formula: read as `c ? x[i] : y[i]`. Java evaluates the
  condition, then the position, then reads the chosen window, and every window of a
  formula holds the same rows, so a position outside fails the same way
  (`NoSuchElementException`). Values: `(S.size() > 1 ? I : J)[0]` is `0 0 0 1 2`,
  `(S.size() < 2 ? I : J).get(0)` `0 0 0 10 20`, `S.size() > 1 ? (S.size() > 1 ? I :
  J)[1] : -1` `-1 1 1 2 3`.

### Still unported

- Bucketing by a vector of `float` or `double` (at any depth):
  `UpdateBy#updateBy` (owner question 10).
- Bucketing by a vector of arrays (at any depth): `UpdateBy#updateBy` (owner question 11).
- Cumulative and rolling minimum and maximum of a vector column:
  `ComparableCumMinMaxOperator`. Java allows them (a vector is `Comparable`; seen: the
  cumulative maximum of `[0] ... [5]`), ordering with `IntVector#compareTo` and its
  siblings, lexicographic with the element comparisons of `IntComparisons` and the like.
  Not ported for lack of room; before, Oxhaven refused these as an invalid request, and,
  with no column named, silently left vector columns out where Java includes them. Both
  now refuse as not ported.
- `len` of an expression that reads a window of objects: still refused.
  `len(S.subVector(0, 2))` is 2 in Java (a slice of a window of strings makes a typed
  array), but the expression crate refuses `subVector` of an object vector, so the formula
  never reaches this check; `len(c ? S : T)` throws `ClassCastException` for every row in
  Java, as `len(S)` does, and stays refused.
- `[]`, `get`, `subVector` or a reading function of a window chosen by a cast, of a slice
  chosen by a condition (`(c ? x : x.subVector(0, 1))[0]`), or of a condition between
  windows of different types; `binSearchIndex` of a slice. Left as they were.

### Differs from Deephaven

- Nothing new. As before, Oxhaven's vector cells are values: a bucket key read from a
  refreshing `group_by` result in Java is a view of the group, which Oxhaven does not
  model.

## Owner questions

10. `update_by` bucketed by a vector of `float` or `double`. Java's buckets depend on the
    class of the vector objects: `DoubleVectorDirect#equals` compares two direct vectors
    with `Arrays#equals` (`-0.0` and `0.0` differ, NaN equals NaN) and anything else with
    `DoubleComparisons#eq` (they are equal). Seen on Deephaven 42.9: `[0.0]` and `[-0.0]`
    are one bucket in a `group_by` result (`DoubleVectorColumnWrapper`), two after a
    `select()` (`DoubleVectorDirect`), and a mix of both pairs them by which is compared
    with which. Recommended: serve with `-0.0` equal to `0.0` and every NaN equal, the
    rule of `DoubleComparisons` and of scalar keys (PARITY.md), and record it as a
    difference for materialized vectors; the alternative is to keep refusing.
11. `update_by` bucketed by a vector of arrays (for example a rolling group of an array
    column). `ObjectVector#equals` compares the arrays by value (`Objects#deepEquals`)
    but `ObjectVector#hashCode` hashes them by identity, so equal vectors fall in one
    bucket only when the hashes happen to collide. Seen on Deephaven 42.9: each of the
    equal `[[0]]` in its own bucket. Recommended: keep refusing (A15 kind); the
    alternative is a bucket per row, which reproduces what Java almost always does.
