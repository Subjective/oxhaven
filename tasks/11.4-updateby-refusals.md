### Done

- R1: the minimum and maximum of a vector column. The cells are decoded with the
  aggregations' `Scalar` (`ops/agg`), ordered by `Scalar::compare`: element by element
  with each type's Deephaven comparison (null first, NaN last, `-0.0` equal to `0.0`,
  strings by UTF-16 code unit), then the shorter first. The cumulative operator keeps the
  first of equal vectors (seen: `[-0.0] [0.0] [-0.0]` gives `[-0.0]` throughout); the
  rolling one keeps the extreme of the window, which for these types is a single value.
  Null cells are skipped, and an empty vector is the least. With no columns named, the
  operators take vector columns, as Java does (`applicable` already said so).
- R21: count-where filters of vector and array columns use the same filters as `where`;
  the refusal is removed.
- R6 to R8: a read by position, a `subVector` or a reading library function of a
  condition whose sides are windows or slices of windows of one type is moved into each
  side (`hoisted`, `on_sides`), as the 10.8 work did for conditions between windows: Java
  evaluates the condition, then the read's arguments, then reads the chosen vector, and
  all windows hold the same rows, so the outcome and the failures are the same. A
  condition between windows of different types is refused by the expression crate, as
  Java refuses it ("Incompatible types in condition operation not supported").
- R11: `len` of a condition between windows of objects fails every row with the same
  `ClassCastException` as `len` of one window.
- Owner question 7.10 added to the second batch (R3).

### Differs from Deephaven

- Nothing new. As before, Oxhaven's vector cells are values: a vector of a refreshing
  `group_by` result is a view of its group in Java, and the minimum or maximum Java keeps
  of one is that view.

## Owner questions

7.10 (added to the second batch). Rolling minimum or maximum of a vector of `float` or
`double`. Java orders vectors with `-0.0` equal to `0.0`, keeps the earlier of two equal
vectors as rows enter, and, when the one it holds leaves, takes the extreme its ring
buffer evaluates, which for equal vectors depends on where they sit in the buffer. Seen
on Deephaven 42.9: over 400 rows alternating `[-0.0]` and `[0.0]`, `rolling_min_tick`
with `rev_ticks=3` gives the earliest vector of the window except at rows 128, 256 and
384. Recommended: serve, keeping the earliest of equal vectors, with the sign of a zero
as a documented difference; the alternative is to keep refusing.
Answered 2026-11-20 by the owner ("Do what's recommended", item 7.10 of the second batch):
served, keeping the earliest of equal vectors in the window. Done in task 14.1; allowed
difference A20 of `PARITY.md`.

7.6. `update_by` bucketed by a vector of `float` or `double` (R4). Answered 2026-11-20 by
the owner ("Do what's recommended", item 7.6 of the second batch): served, with `-0.0` equal
to `0.0` as for a plain `double` column; a vector of vectors of `float` or `double` stays
refused, as the answer does not name it. Done in task 14.1; allowed difference A19 of
`PARITY.md`.

## Handover

- R13 and R15 (rolling formulas over vector and array columns) need vectors of vectors
  and of arrays in the expression crate: `size()`, `[]`/`get` giving a vector or array,
  and a result column of the element's vector type. Seen on Deephaven 42.9 over the table
  of `count_where_source` with `rev_ticks=2`: `x.size()` and `V.size()` give `1 2 2 2 2`,
  `x[0]` and `V[0]` give `[5, 1] [5, 1] [3, 7, 2] null [5, 1]` as an `IntVector` column,
  `x[0].size()` and `x[0].length` (of an array) fail with `NullPointerException` on a
  null cell, `isNull(x[0])` fails with `ClassCastException` (Boolean to Byte, already
  reproduced for objects), and `count(x)`, `first(x)` are refused at compile time
  ("Cannot find method").
- R9 (`binSearchIndex` of a slice): reachable once the expression crate takes the `BS_`
  constants. Java's binary search reads positions by `get`, so a slice reaching outside
  the window fails only when the search visits such a position; a probe would have to
  follow the search over the window's values (`BinSearch#binarySearch0`,
  `#binarySearch0Modified`, which reads both ends first). Seen: within the window,
  `binSearchIndex(I.subVector(0, 3), 3, BS_ANY)` guarded by `I.size() > 2` is `3 2 1` on
  the full windows of `I` = 0 to 4; `subVector(0, 2)` from the first row fails.
- Casts of a window to a vector type (`((IntVector) I)[0]`) are served by Java (seen: as
  `I[0]`) but refused by the expression crate before `update_by` sees them.
