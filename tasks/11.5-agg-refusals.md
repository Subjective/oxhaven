### Done

- A19: `Values` holds a `BigDecimal` or `BigInteger` cell as it is stored
  (`Scalar::Big`), so first and last of every kind of parent, and the values of sorted
  first and last, carry it with its scale. Nothing orders or computes with one:
  `Scalar::compare` refuses it as a broken invariant, and A20 is refused before any
  operator is made. The Kafka change-data-capture refusal of decimals in the current rows
  (owner item 4.3, `docs/KAFKA.md` item 30) is removed.
- A1, A4: a vector key column of the types A1 names goes to the key table's row encoding,
  which compares lists exactly as Java's `equals` does for these elements; an array key
  column is Java's `IllegalArgumentException` text (`AggregateError::ArrayKey`), checked
  where Java checks it.
- A9: distinct vectors of integers, `char`s and strings, through the existing sorted
  multiset (`Scalar::compare` orders vectors as Java does).
- A12: the refusal is removed; the filters are those of `where`, as 11.4 found for
  `update_by`.
- A20: what was an `UnsupportedType` error or a failed table is now an `unported!` refusal
  naming the aggregation and the type.
- Owner question 7.13 added to the second batch (A9c).

## Handover

- A20, the arithmetic and orderings of big numbers. Seen on Deephaven 42.9 over groups
  `[1.0, 1.00, 2.5]` and `[3, null, 3.000]` (and the same as `BigInteger`): sum `4.50` and
  `6.000` (`4` and `6`), abs sum the same, avg `1.50` and `3.000` (`1` and `3`, a
  `BigDecimal`), var `0.7500` and `0.000000` (`1` and `0`), std `0.8660254038` and `0`
  (`1.0000000000` and `0`), min `1.0` and `3` (the first of equal values), max `2.5` and
  `3`, median `1.00` and `3.000`, count distinct 3 and 2 (by `equals`, scale counts),
  distinct `[1.0, 1.00, 2.5]` and `[3, 3.000]`, unique null and null (two values);
  sorted first by a decimal keeps the first of equal values (`1.0` before `1.00`), a null
  first. These need an arbitrary precision decimal type (a new dependency) and Java's
  rounding (`BigDecimalChunkedAvgOperator`, `BigDecimalChunkedVarOperator`, the scale-10
  square root). On a ticking table the scale of a running sum keeps the largest scale
  ever added or removed (`BigDecimal#subtract`), and which of two equal values a minimum
  shows depends on the sorted set's history: both are likely owner questions before a
  port.
- `select_distinct` and joins on vector columns are still refused in their own modules
  (`ops/distinct/keys.rs`, `ops/join/keys.rs`); the key table now groups vectors for
  aggregations, so the same rule (A1) could serve `select_distinct`.
