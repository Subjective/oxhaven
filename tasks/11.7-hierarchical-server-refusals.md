### Done

- S1: `object_texts` gives Java's `toString` of a `Duration` (sign on each part, as many
  digits of fraction as needed), a `Period`, a `ZoneId` (its id), a `ZonedDateTime` (the
  offset from the time zone database, the zone in brackets when it is not that offset), a
  table (`QueryTable`, as the wire already sent it) and a column declared `Object` (the
  text of its class). `has_object_text` follows.
- Found on the way, not an `unported!`: `ApplyPreviewColumns` without a list of types
  wrapped no column but previews and lists. Java also wraps every type
  `ColumnPreviewManager#isColumnTypeDisplayable` refuses: `Duration`, `Period`, `ZoneId`,
  `LocalDateTime`, `DayOfWeek`, `Object` and table columns. Now the same (S1 made those
  previews possible).
- E1 to E3t: sort keys for `BigDecimal` and `BigInteger` are bytes that order as the
  numbers (sign, power of ten of the first digit, the digits without trailing zeros, inverted
  for a negative number), so `1.0` and `1.00` tie and keep the parent's order. A table
  column is refused with Java's text. An absolute sort of `char` is the plain sort; of any
  type without `abs`, the error `String` already had.
- E5, E13: the class names come from the aggregations' `java_class` (`Class#toString`).
- E9: every column that is not a vector or array is left as it is.
- E15: `where_in` keys of the `java.time` types, each class matching only itself.
- Owner questions 7.14, 7.15 and 7.16 added to the second batch.
