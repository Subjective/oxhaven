### Done

- The hash table's `canonical` layout accepts binary cells (`BigDecimal` as scale and
  minimal unscaled bytes, `BigInteger` as minimal bytes, so byte equality is `equals`)
  and lists of such types. The join key cells (`ops/join/keys.rs`) gained bytes and lists.
  `is_ported_key` and `groupable_vector` in `ops/key_table.rs` say which list types are
  keys everywhere.
- Sort keys of vectors and arrays are Arrow row-format lists of the elements' comparable
  form; the descending form inverts the whole encoding, as Java negates the comparison.
- `ComparableCells` (`ops/sort`) gives the row-format cells of the other `Comparable`
  classes; `merge_sorted` and range joins compare those bytes.
- As-of stamps of `BigInteger` use the sort's `big_number_key`; vector stamps are lists
  of stamps.
- `CreateInputTable` with no key columns makes the keyed input table; a delete from it is
  checked as Java's default `validateDelete` checks it.
- Owner question 7.18 added to the second batch.
