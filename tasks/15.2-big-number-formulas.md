## Scope

Owner's go-ahead (25 November: "Refusals, docs, Docker and HTTPS"). Serve formulas that compute with big numbers:
`BD + 1`, `BD * D`, `-BD`, `BI / 3`, casts between big numbers and primitives, the method calls Java's
formula language allows on them, and big numbers as arguments of the built-in functions that take them. Results
must equal Java's exactly, scale included (`BigDecimal#toString` text).

**Dependency.** A decimal type may come from a well-known crate under MIT or Apache-2.0 (for example `bigdecimal` or
`num-bigint`; check the whole new dependency tree with the licence check the `rules` job runs). Any other licence:
stop and report. Do not translate JDK source (`java.math`); implement from documented behaviour and fixtures recorded
from Java.

If a case cannot match Java exactly, keep it refused and list it; do not add PARITY.md entries.

## Notes

Built: `crates/oxhaven-expr/src/decimal.rs` (a decimal over `num-bigint`, already in the lock file through arrow, MIT
OR Apache-2.0; written from the documented behaviour of `java.math`, not its source), the checker in
`types/big.rs` and the evaluator in `eval/big.rs` (`Node::Big`, row by row). A big number column is now a value like
any other: operators of `QueryLanguageFunctionUtils` with every primitive and each other, `-`, casts to and from the
primitives and `(java.math.BigDecimal)`, the methods of both classes (with `RoundingMode` constants and the legacy
`int` modes), `valueOf`, the constants, the constructors (literal and column strings, numbers, `BigInteger` with a
scale), `minObj`, `maxObj`, `ifelseObj`, `replaceIfNull` and the operator functions called by name.

Recorded: `crates/oxhaven-expr/tests/data/java_big_numbers.{txt,json}` (773 formulas run on Java 42.9 embedded by
`record_java_big_numbers.py`, values as `toString` text so the scale shows); 726 agree, none differ, 47 are refused
and listed in `java_big_numbers_refused.txt`. The oracle scenario `formula_big_numbers` (client table operations,
text columns for scale) was recorded on the Java server. Java's validator lets a client use the constructors,
static methods and fields of both classes (checked over gRPC), so the request compiler refuses nothing more.

Still refused: `MathContext` arguments, `hashCode`, `getClass`, `toEngineeringString`, the `*Exact` methods, `sqrt`,
`modPow`, `isProbablePrime`, `divideAndRemainder`, `(Object)`/`(Number)`/`(Comparable)` casts, `RoundingMode` as a
value, `inObj`, `inRange`, `countObj`, `firstObj`, `sortObj`, `distinctObj`, `countDistinctObj`, `vecObj`,
`String.valueOf` and `Objects.equals` of a big number. `new BigDecimal(String)` of text that is not ASCII stops with
`unported!` (Java reads other digits through `Character#digit`). A power of ten or a shift of more than a million
digits (four million bits) fails where Java would take very long or run out of memory (PARITY A12's case).
