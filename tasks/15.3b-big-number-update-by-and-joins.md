## Notes

- Served, static and ticking, with Java 42.9's values and scales: cumulative sum, product, min, max,
  forward fill and delta (all three controls); rolling sum, avg, product, std, min, max, count and
  weighted average by ticks and by time, of `BigDecimal` and `BigInteger` (weights of any numeric or big
  type). Java's arithmetic at a `MathContext` is `update_by/big.rs`, checked case by case on OpenJDK 21;
  the request's math context reaches it (`UpdateByControl`, default `DECIMAL64`).
- Ticking results depend on where Java's pass over the affected rows starts (a rolling sum of a modified
  row is `8` where a static table gives `8.000`). Oxhaven recomputes the same rows in the same order, so
  it matches; random tests use one scale and few digits, and the history-dependent cases are in
  `big_tests.rs` and the new scenario `oracle/scenarios/ticking/ticking_update_by_big_numbers.json`
  (seven steps; replays clean).
- Refused as unported: the exponential operators of big numbers (review item 8.3: the decay is the
  decimal of HotSpot's `Math.exp`), and a weighted average with big weights of a column Java has no plain
  cast to `BigDecimal` for.
- Joins: `BigInteger` as-of stamps and range values were served already; `BigDecimal` as-of stamps and
  range values stay refused, as ruled for review item 7.18.
