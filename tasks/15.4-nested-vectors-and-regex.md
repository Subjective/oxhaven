## Scope

Owner's go-ahead (25 November). Two parts, in order; push after each.

1. **Vectors of vectors** (a `group_by` of a vector column, and what reads it): formulas that index or iterate
   them, `ungroup` of one level, and the aggregations and `update_by` operators that do not order them. Orderings of
   them stay refused (owner item 2.2).
2. **Regular expressions** in `matches` filters: lookaround, back references, possessive quantifiers and atomic
   groups through `fancy-regex` (MIT; check its dependency tree's licences). Translate Java's syntax and case
   folding to it; record Java's answers with `java.util.regex` on the reference's JDK; never translate JDK source.
   Whatever cannot match Java stays refused.

## Notes

Part 1, vectors of vectors (seen on Java 42.9, recorded in `oracle/corpus/nested_vectors` and
`ticking_nested_vectors`):

- In a formula column an element of an `ObjectVector<IntVector>` (or of another primitive or string vector) is
  the inner vector, read as a vector column's cell is. Formulas index, size and iterate them.
- Java gives an element of a vector of string vectors, `(X)`, a ternary of `X`, `X_` and an inner vector of
  Booleans without their element type (`Object` or strings); those stay refused.
- In a filter (`ConditionFilter`) the column is a raw `ObjectVector`, so an element is an `Object`: a filter that
  reads an element is `unported!`; sizes and nulls are served.
- `forward_fill` of a vector of vectors gives `ObjectVector<Object>` (a client receives strings): `unported!`.
- Ungroup, first/last/count/count_where/group aggregations, rolling count and count-where, match filters,
  `select_distinct` and `sort` by other columns already served vectors of vectors; orderings stay refused (2.2).

Part 2, regular expressions (JDK 21's `java.util.regex` asked directly from a program that calls `Pattern.compile`
with `DOTALL` and optionally `CASE_INSENSITIVE` and `Matcher#matches`; 450 patterns, hand-picked and drawn at
random, each on 44 short strings, in `ops/filter/java_backtracking.txt`; and the scenario
`filter_regex_backtracking` recorded on Deephaven 42.9):

- `fancy-regex` 0.20.2 (MIT) brings `bit-set` and `bit-vec` (both Apache-2.0 OR MIT); the rest of its tree
  (`regex-automata`, `regex-syntax`, `aho-corasick`, `memchr`) was already in the workspace.
- Served: lookahead, lookbehind of bounded length, atomic groups, possessive quantifiers (`X*+` as `(?>X*)`), back
  references by number (as many digits as name a group opened before, one at least) and by name. A reference to a
  group the pattern does not have never matches. Patterns without these still go to the `regex` crate.
- Refused (`unported!`): a back reference where case is ignored (Java folds US-ASCII only); a back reference to a
  group in a repetition, an atomic group or a lookaround (Java keeps a value captured on a path it gave up:
  `(?>(a))*\1` matches `a`, `(a*)+\1` matches `aaa`); a quantifier of a lookaround; a repetition without bound or a
  back reference in a lookbehind (Java accepts `a(?<=a*)b` and refuses `(?<!A{2}+.++)`, by a rule not
  documented); what `fancy-regex` refuses; a match that takes `fancy-regex` more than a million steps.
