## Scope

The table service with a registry mapping each of the 41 batch operations to a handler. Implement `Batch` (including references between operations in one batch), `EmptyTable`, `TimeTable`, `FetchTable`, `MetaTable`, `ExportedTableUpdates` and `GetExportedTableCreationResponse`. Every operation without a handler returns gRPC `UNIMPLEMENTED` naming the operation. Later operator tasks add one handler each and touch nothing else here.

## Notes

Adding an operation: write `crates/oxhaven-server/src/table/ops/<name>.rs` with a `Handler` that implements `TableOp`, and add one line to the `handlers!` list in `ops/mod.rs`. The module documentation of `ops/mod.rs` describes the trait and `table/support.rs` holds the shared helpers (source references, column checks, formula compilation, error mapping). An operation whose source is refreshing runs under the shared lock of the update graph without the handler asking for it.

The protocol has 42 batch operations, not 41: `LEFT_JOIN` and `AS_OF_JOIN` are deprecated but Java still registers them.

Built outside `src/table/` because the table service needs it:

- `src/schema.rs`: the Arrow schema Java sends for a table. Shared with the Flight service.
- `src/update_graph.rs`: `PeriodicUpdateGraph`, the cycle driver the server owns (1000 ms by default, `--cycle-ms`). `run_cycle` asks the driver for a cycle and waits for it, so an input table write is a request and a wait.
- `src/session/export.rs`: `Export::failure()` and `From<TableFailure> for ExportError`, which the batch error text needs.
- `src/test_support.rs`: a server on a loopback port for service tests.

Not ported, each an `unported!` in `ops/time_table.rs`: a start time in a zone other than UTC or with a region that differs from its offset, a signed year, and hour 24. `schema.rs` has one for a column type it does not know.

The schema omits `deephaven:tableMetadata`, column descriptions and component types; no table of this engine carries them yet.

Differences from Java seen against the oracle:

- A batch operation with no table reference: Java resets the stream, this server answers `INVALID_ARGUMENT`.
- A duplicate export id gets the same code with a different message.
- The schema flatbuffer is 8 bytes longer than Java's for the same schema. Both decode to the same schema.

`client-smoke tables` against this server passes 1 of 6 (`time_table` schema and refreshing flag). The other five need `Update`, `UnstructuredFilter` or Flight `DoGet`/`DoPut`, so the second half of the gate cannot pass until those tasks land. `client-smoke session` passes 3 of 8 for the same reason.

To run the server for the harness: `OXHAVEN_PSK=oxhaven target/debug/oxhaven-server --host 127.0.0.1 --port <port>`.
