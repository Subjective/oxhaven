## Notes

Done on branch `task/2.3-flight` together with 2.3.

`CreateInputTable` is an operation of the table service (task 2.2). This task provides what
it calls:

```rust
pub fn create_input_table(
    graph: Arc<dyn UpdateGraph>,
    request: &CreateInputTableRequest,
    source: Option<&Arc<dyn Table>>,
) -> Result<Arc<dyn Table>, Status>
```

`source` is the table `source_table_id` names, resolved by the caller.
`validate_create_input_table` is the check Java makes before it resolves the source.

`AddTableToInputTable` and `DeleteTableFromInputTable` answer when `InputTable::add` or
`delete` returns, which is when the change is visible in the input table. Their status codes
match the capture `flight/fixtures/input_calls.status`, and what a client then reads matches
`input_keyed_after_delete`.

Answer `UNIMPLEMENTED` ("not ported yet: <java method>"), because the engine's input tables
lack them:

- `TablePublisher#of`: the blink kind
- `KeyedArrayBackedInputTable#make`: a keyed table without key columns, and a `float` or
  `double` key column

Differences and gaps:

- `crate::schema` writes `deephaven:tableMetadata` (base64 of a protobuf naming the key and
  value columns; PARITY.md Q8) as Java does for every input table, so the whole schema of
  an input table equals Java's. Column restrictions are not in it: no table here has any.
- The `InputTable` contract has no `validateAddOrModify` and `validateDelete`; the service
  compares definitions itself before it calls `add` or `delete`.
- A failure while a change is applied is `DATA_LOSS` as in Java; no test reaches it.

The table service handler is `table/ops/create_input_table.rs`. On the server's periodic
update graph a change waits for the driver's next cycle, which `InputTable::add` and
`delete` request themselves.

Gate, with main merged: `cargo test -p oxhaven-server inputtable` passes.
`replay --ops input_table --within input_table` is clean (1 scenario). `client-smoke
inputtable` passes 3 of 5; "keyed input table" needs the `View` handler and "derived tables
follow an input table" needs `Aggregate`. It passes 5 of 5 against Java.
