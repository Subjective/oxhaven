## Scope

The config service (authentication constants and configuration constants the web client reads), a gRPC-web transport on the same port, and the browser-streaming variants of bidirectional calls that the JS client uses in place of true bidi streams.

## Notes

The config service (`src/config/`) is done on the branch of task 2.2: `GetAuthenticationConstants` and `GetConfigurationConstants`. It leaves out `java.version`, `groovy.version` and `python.version`, which describe a runtime this server does not have. The gRPC-web transport and the browser-streaming calls are still open.

The gate command as written is refused by cargo, which takes one test name filter. `cargo test -p oxhaven-server config` runs the config tests.

The transport is `src/transport/` and the static files `src/web/`, both on the gRPC port, which
the server now accepts itself (HTTP/1.1 and HTTP/2 without TLS by prior knowledge) instead of
through tonic's server, because tonic does not hand over upgraded connections:

- `transport/websocket.rs`: gRPC over a websocket, subprotocols `grpc-websockets-multiplex` and
  `grpc-websockets`, bridged into the same service stack as native gRPC. This is the only
  transport a browser on an `http://` page uses.
- `transport/browser.rs`: gRPC-web over HTTP/2 (binary mode, as Java), the CORS answers, the
  headers Java adds to every response, and Java's refusal of gRPC over HTTP/1.1.
- `web/`: `/ide/`, `/iframe/`, `/jsapi/` from the directory given with `--web-root`, and the
  empty `/js-plugins/manifest.json`. `scripts/extract-web-root.sh <directory>` fills a
  directory from the `deephaven-web` jar of an installed `deephaven-server` wheel; the files
  must stay out of the repository. Without `--web-root` those paths answer `404`.

Not done:

- `BrowserFlightService` has `OpenDoPut`/`NextDoPut` only, added by task 7.8: the web client
  uploads a table with them whatever its transport. `OpenDoExchange`/`NextDoExchange` and the
  handshake pair answer `UNIMPLEMENTED`. The browser uses those only on an `https://` page,
  and the server has no TLS.
- No `Content-Encoding: gzip` for static files, no byte ranges, and `ETag` values of our own.
- HTTP/2 without TLS is by prior knowledge only; Jetty also takes the `Upgrade: h2c` request.
- A call's `grpc-timeout` ends it only until its response headers, as with tonic's server
  before; Java ends a streaming call at its deadline too. Calls over the websocket have no
  deadline, as in Java.

To see the IDE against the server:

```bash
scripts/extract-web-root.sh /tmp/oxhaven-web
cargo run -p oxhaven-server -- --port 10100 --psk oxhaven --web-root /tmp/oxhaven-web
node oracle/ide/ide-test.js --url dh+psk://oxhaven@127.0.0.1:10100
```
