## Scope

Array and vector columns at the server's wire boundary: describing nested lists, accepting list columns in a Flight `DoPut`, sending them in `DoGet`, Barrage snapshots and subscriptions, and `ApplyPreviewColumns`, which is how the web IDE shows them. Not part of it: Arrow types Java reads by converting (wider integers, other time units, `FixedSizeList`, `ListView`, `Binary`), and the text of a Java array object.

## Notes

- Describe. `wire_columns.rs` says how a column type is sent where that is not its stored
  Arrow type: a `byte[]` as `Binary` with a null element as the byte `0x80`
  (`DefaultChunkWriterFactory#binaryFromByteArray`), and the elements of an `ObjectVector`
  that is itself an element as `Utf8`, each the `toString` of the element
  (`BarrageUtil#arrowFieldForVectorType`, `DefaultChunkWriterFactory#utf8FromObject`). So
  `group_by` of `group_by` of a `String`, `Boolean` or `Instant` column is
  `list<list<utf8>>`, as Java sends it, and a third `group_by` sends the text of the inner
  vectors (`[1]`, `[ ]`, `[-3,1]`; ten elements, then `, ...]`). `DoGet` and the Barrage
  producer convert the chunks they read with `WireColumn::cells`. `java_text.rs` has Java's
  `toString` of the boxes, `Instant`, and the vector classes.
- Upload. `BarrageUtil#getDefaultType`: a list without `deephaven:type` is an array of its
  elements' default type at any depth. With a type it is that class; an `ObjectVector`
  holds its `deephaven:componentType`, or without one its element field's default type.
  The table keeps the cells in the Arrow type of its column type, with Deephaven's null
  values turned into nulls in the elements too, and answers `GetSchema` with the fields the
  client sent, as before. Refusals, with Java's codes: a component type that is not the
  element class of the type and an `ObjectVector` of a primitive are
  `IllegalArgumentException`s in Java, so `INVALID_ARGUMENT` with an error id for the
  upload and `FAILED_PRECONDITION` for a later read of the export; an `ObjectVector` of
  `ObjectVector`, a list declared as a scalar, a scalar declared as an array and a
  `LargeList` without a type are `INVALID_ARGUMENT` for all three calls.
- Preview. `ApplyPreviewColumns` is the engine's `update_view` with a formula per replaced
  column, compiled by a compiler of its own in `apply_preview_columns.rs`: an array or
  vector becomes `Vector#toString(5)` (a null cell stays null), any other column whose type
  the request does not list becomes the first 10000 UTF-16 units of `toString`. The result
  columns are `String` columns to the engine. `schema.rs` keeps, beside the result table,
  that they are previews, and describes them as Java does: `deephaven:type` is
  `…preview.ArrayPreview` or `…preview.DisplayWrapper`, `deephaven:description` is
  `Preview of type: <class>` followed by the description the column had, there is no
  `isSortable`, and the schema has the unsent attributes `ColumnDescriptions` and
  `PreviewParentTable`. The two differences `ide/mod.rs` listed for
  `ApplyPreviewColumns` are gone; the recorded Java answers match now.
- `unported!`, two, both `java.lang.Object#toString`: the text of an array that is an
  element (`java_text::object_texts`; Java prints `[I@1b6d3586`, the class and the
  identity hash), reached by a fourth level of grouping over arrays, and the same refused
  up front by `ApplyPreviewColumns` for a column whose elements are arrays or vectors of
  arrays (`int[][]`, an `ObjectVector` of `int[]`), so that no read of the result panics.
  Answered `UNIMPLEMENTED` by a status, where a client can reach it in an upload:
  `BarrageUtil#getDefaultType` for a list of non-nullable `Bool` (Java's `boolean[]`),
  `FixedSizeList`, `ListView` and `Binary`; `BarrageUtil#convertArrowSchema` for a class
  name there is no column type for (`java.lang.Integer` as a component, an unknown class,
  for which Java answers `INVALID_ARGUMENT`); `DefaultChunkReaderFactory#newReader` for an
  Arrow type that is not the stored one (`list<int64>` as `int[]`, `list<timestamp[ms]>`,
  and `list<int32>` as `String[]`, for which Java answers `INVALID_ARGUMENT`).
- Known differences from Java, besides those:
  - A table derived from an upload is described from its definition. Java passes the
    uploaded schema on through some operations (`where`): its `byte[]` column stays
    `list<int8>` there and is `Binary` here.
  - A table derived from a preview table (`head`) has `java.lang.String` columns that are
    sortable. In Java they keep the class `ArrayPreview` and lose the description.
  - `ApplyPreviewColumns` refuses the whole table when one column would hold the text of
    an array, where Java previews every column.
- Contract gaps. A column type cannot say that a column is a preview (Java's column
  definition has the class `ArrayPreview`), and a table has no attribute for column
  descriptions, the preview's parent or the schema an upload came with. The server keeps
  all three beside the table, found by the table's address (`schema::remember_previews`,
  `flight::wire::remember_uploaded`), which is why they do not survive an operation.
- Tests. `flight/fixtures/capture.py` gained `lists`, recorded from Java 42.9: four
  uploads of every element type (arrays, nested arrays, vectors, vectors of arrays) and
  one of long cells, with `GetSchema`, `GetFlightInfo` and `DoGet`; `ApplyPreviewColumns`
  with the web IDE's type list over three of them; six refused uploads with the status of
  the upload and of the reads after it. `flight/tests.rs` replays them through gRPC and
  checks the types `convert_schema` gives 14 fields and its 15 refusals.
  `apply_preview_columns.rs`, `java_text.rs`, `wire_columns.rs` and `list_columns.rs` have
  the unit tests, with texts recorded from Java.
- Checked live against Java 42.9 on 2026-11-15 with scratch scripts, not in the
  repository: 120 uploads (element type × nesting × metadata), all with Java's type or
  Java's refusal; `DoGet`, Barrage snapshots (full, viewport, column subset, reverse,
  Deephaven nulls) and subscriptions of uploaded, grouped and input tables with list
  columns, a changing viewport and modified list cells, and of preview tables: 246
  messages, compared as decoded metadata, field nodes, buffers and body bytes, no
  difference; the web IDE (`/iframe/table/`) on a `group_by` with `int`, `String`,
  `double`, `Boolean` and `Instant` vectors, a null element and a group of six: the grid
  painted the same cells on both servers.
- Mutation check: 54 single-line breaks of `upload.rs`, `java_text.rs`, `wire_columns.rs`,
  `apply_preview_columns.rs`, the preview part of `schema.rs`, and the conversions in
  `barrage/producer.rs`, `flight/wire.rs` and `flight/encode.rs`, each run against
  `cargo test -p oxhaven-server --lib`. 43 failed a test, 1 did not compile and 10 passed.
  Of the 10, 7 showed missing tests, which were added and fail for them now (an array of
  `ObjectVector` as a type name, arrays of arrays of bytes, a converted column in `DoGet`,
  in a Barrage snapshot and in a Barrage update, the cut of a long text through the
  preview, and previous values of a preview column); 1 broke a condition that could not
  change a result, which was removed; 2 change nothing that can be observed (a vector of
  bytes is never below a converted column, and `update_view` without columns is the
  source itself).
