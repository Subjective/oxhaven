## Scope

Parser, type checker and vectorized evaluator for the smallest useful subset: column references, literals, `+ - * / %`, comparisons, `&& || !`, parentheses, and `isNull`. Numeric promotion, null propagation, overflow and division behavior must follow Java as recorded in PARITY.md; `QueryLanguageFunctionUtils` defines the binary-operator semantics per type pair. Anything else is a parse error that names the unsupported construct.

The harness reaches formulas only through table operations on a server, and this task has none, so its gate has no oracle part. The oracle checks these semantics in the gates of tasks 3.2 and 3.4.

## Notes

- Implements `FormulaCompiler` and `Formula` from `oxhaven_contracts::expr` as `oxhaven_expr::Compiler`. It does not depend on `oxhaven-column`; tests use a table backed by Arrow arrays.
- Layout follows the owners of the later tasks: `src/parse/` (lexer, parser), `src/types/` (type checker), `src/eval/` (evaluator), `src/functions/` (registry, `isNull` only).
- Beyond the listed scope it accepts `==`, `!=` and ordering on `String` and `Instant`, `==` and `!=` on `Boolean`, and `x == null` / `x != null`.
- Reported as `Unsupported`, by name: ternary, casts, method calls, field access, calls other than `isNull`, `i` / `ii` / `k`, column arrays, `& | ^`, string concatenation, `Instant` arithmetic, ordering of `Boolean`, comparisons across kinds (for example `int` with `String`), time literals, escaped char literals, octal literals, an uppercase `F` suffix, unicode escapes and single quotes in strings, comments.
- `tests/formulas/corpus.rs` checks the `update`, `view` and `where` formulas of the oracle scenarios against `oracle/corpus`. `python oracle/run.py replay --ops expr_minimal` was not run: there is no such entry point.
