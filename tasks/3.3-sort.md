## Scope

`sort` (multi-column, ascending, descending, absolute; stable; null and NaN ordering per PARITY.md), `head`, `tail` and `slice`. The incremental sort may use a simpler structure than Java's as long as results match. Build the static path first and get it through the gate, then the incremental path. Add the gRPC handler for these batch operations. Run every engine test with the consistency checker attached.

## Gate

```bash
cargo test -p oxhaven-engine sort && oracle/bin/harness replay --url "$OXHAVEN_URL" --ops sort,head,tail --within sort,head,tail,input_table && oracle/bin/harness fuzz --a "$JAVA_URL" --b "$OXHAVEN_URL" --ops sort,head,tail --seeds 10000
```

`$OXHAVEN_URL` and `$JAVA_URL` are described in `tasks/README.md`. The oracle harness does not cover `slice` yet, so this gate does not check it; that needs an oracle task first.

## Notes

- Done together with task 3.5 on one branch: `sort` shifts with `flattened_shift_data` and `reverse` is built on `positional`, both in `ops/merge/flatten.rs`.
- `oxhaven_engine::ops::sort` has `sort`, `reverse`, `head`, `tail` and `slice`, each from an `Arc<dyn Table>` to `Result<Arc<dyn Table>, SortError>`. The variants of `SortError` name the Java exception, for the handler to map to a status; the recordings give `FAILED_PRECONDITION` for `NoSuchColumn`.
- The result of a sort is positional: row key `p` is position `p`, read through a `WritableRowRedirection`. Java leaves gaps in the key space; here an insertion shifts every row after it. Only row keys and shift ranges differ (PARITY.md A4). The table is not marked flat, as in Java, except for a static or blink parent.
- Sort keys are Arrow row-format bytes of the sort columns, kept per row, after NaN, `-0.0`, strings (UTF-16 code units) and absolute values are brought to Java's order. An absolute sort is done in the engine; Java's server does it as `updateView("__ABS__X = abs(X)")`, sort, drop.
- On a blink table: `sort` is each cycle sorted, `head` is `BlinkTableTools.blinkToAppendOnly` with a limit, `tail` is a ring table, `slice` is refused, as in `QueryTable`.
- Not done: the gRPC handler (`crates/oxhaven-server/src/table/ops/sort.rs`), `headPct` and `tailPct` (not in the gRPC surface), and Java's shortcut that returns the table itself when it carries a `SortedColumns` attribute for the first sort column, because `TableAttributes` has no such attribute. Without the shortcut the rows are the same; a static table that is already in order is still returned as it is.
- `unported!`: an absolute sort of a `Char` column (`QueryLanguageParser#visit(MethodCallExpr)`: whether `abs(char)` compiles), and a sort by a column type other than the ten of `ColumnType` (`SortOperation#SortOperation`).
- Tests: `ops/sort/tests.rs` (the order of every type, each incremental case with the exact update, blink tables, random updates over 40 seeds with the checker and a recompute), `ops/sort/corpus.rs` (every result of `oracle/corpus` that is a sort, head, tail or merge of inputs or of such results: 42 tables, 93 comparisons over all steps; the other 145 result tables need other operations). `ops/sort/testing.rs` is test support shared with `ops/merge`.
- Gate: `cargo test -p oxhaven-engine sort` passes. The two `oracle/bin/harness` commands were not run: there is no server for these operations yet.
