## Scope

`merge` (row order is the order of the input tables, then each table's own order) and `flatten`. Build the static path first and get it through the gate, then the incremental path. Add the gRPC handler for these batch operations. Run every engine test with the consistency checker attached.

## Gate

```bash
cargo test -p oxhaven-engine merge && oracle/bin/harness replay --url "$OXHAVEN_URL" --ops merge --within merge,input_table && oracle/bin/harness fuzz --a "$JAVA_URL" --b "$OXHAVEN_URL" --ops merge --seeds 10000
```

`$OXHAVEN_URL` and `$JAVA_URL` are described in `tasks/README.md`. The oracle harness does not cover `flatten` yet, so this gate does not check it; that needs an oracle task first.

## Notes

- Done together with task 3.3 on one branch.
- `oxhaven_engine::ops::merge` has `merge(&[Arc<dyn Table>]) -> Result<Arc<dyn Table>, MergeError>` and `flatten(&Arc<dyn Table>) -> Result<Arc<dyn Table>, TableFailure>`. The recordings give `INVALID_ARGUMENT` for `MergeError::IncompatibleDefinitions`.
- `merge` keeps Java's layout: each table has a range of row keys in units of 65536 keys (`UnionRedirection`), a range grows when its table outgrows it and shifts the ranges after it, and it never shrinks. The result has the first table's columns; the others are matched by name. Attributes follow `PartitionedTableImpl#computeSharedAttributes`.
- `flatten` returns a flat table itself. Otherwise row key `p` of the result is position `p` of the parent, and every added or removed row shifts the rows after it.
- Not done: the gRPC handlers (`crates/oxhaven-server/src/table/ops/merge.rs`), the `key_column` of `MergeTablesRequest` (`mergeSorted`), and the unpacking of a constituent that is itself a merge into its own constituents (`TableToolsMergeHelper#getTablesToMerge`), which changes row keys only. A merge of no tables is refused with Java's message for no non-null tables; a Rust caller cannot pass a null table.
- No `unported!`.
- Tests: `ops/merge/tests.rs` (static and ticking merges, growth of a range, blink tables, attributes, flatten, random updates over 40 seeds on three sources with the checker and a recompute), unit tests in `union.rs` and `flatten.rs`, and the merge results in `ops/sort/corpus.rs`.
- Gate: `cargo test -p oxhaven-engine merge` passes. The two `oracle/bin/harness` commands were not run: there is no server for these operations yet.
