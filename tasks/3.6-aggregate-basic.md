## Scope

`aggregate` with sum, count, min, max, first, last and avg, keyed and unkeyed. Build the keyed state manager and the operator interface that task 4.1 extends: one generic implementation in place of Java's per-type operator classes. Group order and result types per PARITY.md. Build the static path first and get it through the gate, then the incremental path. Add the gRPC handler for these batch operations. Run every engine test with the consistency checker attached.

## Gate

```bash
cargo test -p oxhaven-engine agg && oracle/bin/harness replay --url "$OXHAVEN_URL" --ops agg_by --within agg_by,input_table && oracle/bin/harness fuzz --a "$JAVA_URL" --b "$OXHAVEN_URL" --ops agg_by --seeds 10000
```

`$OXHAVEN_URL` and `$JAVA_URL` are described in `tasks/README.md`. `agg_by` is the harness name for `aggregate`; it covers `sum`, `count`, `min`, `max`, `first`, `last` and `avg`. The oracle harness does not cover any other aggregation yet, so this gate does not check it; that needs an oracle task first.

## Notes

- `ops::agg::aggregate(parent, aggregations, preserve_empty, group_by)` is `Table#aggBy`. The
  module comment of `ops/agg/mod.rs` says how to add an aggregation.
- One operator per result column implements `AggOperator`. It is given the rows of one group
  within one chunk (a `Run`) and reads them as longs, doubles, booleans or `Scalar`s, so there
  is one sum, one avg, one min/max and one first/last for all column types. An operator that
  cannot retract (min, max, first and last on a table that removes rows) says so with
  `needs_group_rows` and asks for a recompute; only then does the framework keep the rows of
  each group. On static, add-only and blink parents no group rows are kept.
- Rows are processed in chunks of 4096 with one operator call per group and chunk, as in
  Java. A `long` sum that passes over the null sentinel depends on that.
- Sum, avg and count keep Java's state in the sentinel domain and port its arithmetic
  statement for statement, including what it does after rounding or wrapping: a `double` sum
  that rounded when a row was added does not get the lost part back when the row leaves, and
  a `long` sum that wrapped onto the null long continues from null. The recorded
  `ticking_agg_by` scenario shows the first.
- An aggregation without keys of an empty table has no row unless `preserve_empty` is set
  (`ChunkedOperatorAggregationHelper#noKeyAggregation`; the corpus agrees).
- Not reproduced: which of `0.0` and `-0.0` a minimum or maximum shows when a group has
  both. Here it is the first one given. Java's `SsmChunkedMinMaxOperator` shows whichever
  its sorted multiset holds, which depends on its sort and merge history (PARITY.md Q4).
- `unported!`: an aggregation output with the name of a group-by column
  (`AggregationContext#getResultColumns`).
- Not built: the gRPC handler (`crates/oxhaven-server/src/table/ops/agg.rs`), which also has
  to parse `"Out = In"` pairs; `initialGroups`; operators with several inputs or outputs.
- Gate: the cargo part passes. The corpus test in `ops/agg/tests/corpus.rs` compares all 48
  recorded results of `agg_by` operations on input tables, and the 7 refusals, with the
  rules of `oracle/harness/rules.py`. Two `agg_by` operations whose source is another
  operation's result are not run (`agg_by_no_keys.all_d`, `pipeline.by_region`). The harness
  commands need a server and were not run.
