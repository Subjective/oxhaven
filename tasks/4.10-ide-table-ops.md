## Notes

- `column_statistics` and `apply_preview_columns` were on main before this task's branch;
  the branch adds `run_chart_downsample` and the `SeekRow` call (the grid's "go to row"),
  which is not a batch operation and was answered `UNIMPLEMENTED`.
- Outside the owned paths: `pub mod ide` in `crates/oxhaven-engine/src/ops/mod.rs`; the
  handler line and `seek_row` in `crates/oxhaven-server/src/table/ops/mod.rs`; the `SeekRow`
  call in `crates/oxhaven-server/src/table/mod.rs`; `table/tests.rs`,
  `table/tests/handlers.rs` and `table/tests/handlers/ide.rs`. Every batch operation now
  has a handler, so the test of an operation without one is gone.
- The result of Java's downsample depends on the order of the changes, not only on the
  parent's rows, so the operator keeps Java's state and the tests cannot compare with a
  recompute: they compare with what Java 42.9 answered (`java_downsample.txt`,
  `java_seek.txt`, recorded over gRPC) and run the consistency checker without one.
- Reproduced from Java, each with a test: a cycle that only removes rows fails the result
  when one was an extreme of a bucket that keeps rows; a result made of no rows or of rows
  of one X value fails when a row arrives; an `Object` Y value made null stays an extreme;
  the buckets outside a zoom range are never read again; a removed or modified row of the
  bin 0 is looked for in the bucket of the row before it.
- Refused, as `unported!` (`UNIMPLEMENTED`):
  - `io.deephaven.engine.table.ColumnSource#allowsReinterpret`: a `long` X column that is
    not held in memory. Java takes a `long` column of some sources (array, redirected,
    union) and refuses others (a formula of a view, `ungroup`); the `ColumnSource` contract
    cannot say which a source is. So the `long` X column of a sorted, joined, merged or
    uploaded table is refused here and taken by Java. An `Instant` X column, which is what
    the IDE's charts downsample, is taken everywhere.
- Refused, as a failure of the result that starts `not ported:`:
  - `RunChartDownsample.DownsamplerListener#handleModified`: a modified row whose X value
    moves it to another bucket (what Java does depends on how the column is stored), and a
    modified row at a row key that held no row before a shift.
  - `RunChartDownsample.DownsamplerListener#notifyResultTable`: a result with rows its
    parent does not have, and a change of the result that the shifts do not lead to. Java
    gets there by not reading the buckets outside a zoom range again, by the bin 0, and by
    keeping the rows a bucket last reported across a shift.
  - `BucketState#shift`, `BucketState#makeRowSet`: states of a bucket Java reads garbage in.
  - `SeekRow#seek`: a starting row or a table size beyond an `int`, a sorted column in a
    table with a row key beyond one, and the text of a value that is neither a `String`
    nor a `char` (the server refuses that literal before the search, as Java does).
- A failed result reads differently: Java goes on serving the rows it had with the values
  they had, here the removed rows read as nothing.
- Java memoizes the downsample on its parent; here every call makes its own.
