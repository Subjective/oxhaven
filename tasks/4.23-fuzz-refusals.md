## Scope

Requests Java computes and Oxhaven refuses. Each gets a regression test that fails before
the change, after the running Java reference (42.9) was probed; then the generator
restriction that hid it is removed and its family run for 1000 seeds.

- R4. Initial groups a refreshing table has no rows for, without `preserve_empty`.
- R7. `keyed_transpose` with `col_by` a `float32` or a timestamp column.
- R8. A period of months or years added to a timestamp that is never evaluated.
- R1. `lazy_update` with `i`, `ii`, `k`, a column array, or a fixed-distance read inside a
  call.
- R6. The column array of an array column.
- The spellings of a time literal that 4.20 left refused by name: a zone directly after the
  time, a region with a `/` that the compiled time zone database lacks (`SystemV/EST5`),
  and the rest of that list, where Java accepts them.

Not part of it: R5 (Java goes stale there, J3), the Java defects J1 to J6, and D5 (the
serving of failed tables, Q11 of `PARITY.md`). The two J1 scenario files are not replayed:
they shut the reference down.

A difference that a lifted restriction exposes is a finding: fixed here when cheap, and
otherwise written up below with a minimal scenario and a narrower restriction that names
it.

## Gate

```bash
cargo test --workspace \
  && for family in formulas2 initial_groups partitions ring transpose script_joins \
       update_by2 statistics all2; do \
       oracle/bin/harness fuzz --a "$JAVA_URL" --b "$OXHAVEN_URL" --family $family \
         --seeds 1000 --keep-going || break; done \
  && oracle/bin/harness fuzz --a "$JAVA_URL" --b "$OXHAVEN_URL" --family all --seeds 1000 --keep-going
```

`$OXHAVEN_URL` is a server built with `--features python` (`tasks/README.md`).
