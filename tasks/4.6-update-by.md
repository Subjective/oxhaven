## Scope

`update_by`: cumulative operations first (sum, min, max, product, forward fill, count), then rolling windows by ticks and by time, then exponential moving operations and delta. Gate each group separately. Build the static path first and get it through the gate, then the incremental path. Add the gRPC handler for these batch operations. Run every engine test with the consistency checker attached.

## Gate

```bash
cargo test -p oxhaven-engine updateby && oracle/bin/harness replay --url "$OXHAVEN_URL" --ops update_by --within update_by,input_table && oracle/bin/harness fuzz --a "$JAVA_URL" --b "$OXHAVEN_URL" --ops update_by --seeds 10000
```

`$OXHAVEN_URL` and `$JAVA_URL` are described in `tasks/README.md`. The oracle harness does not cover update-by operations other than `cum_sum` yet, so this gate does not check it; that needs an oracle task first.

## Notes

- `ops::update_by::update_by(parent, operations, by)` is `Table#updateBy`. Ported: the
  cumulative sum, product, minimum, maximum, forward fill and delta; the rolling sum,
  average, minimum, maximum, count and product over windows in rows or in time; the
  exponential moving average, sum, minimum and maximum decaying by ticks or by time, with
  every `BadDataBehavior`. `unported!`: rolling standard deviation, weighted average, group,
  formula and count-where, cumulative count-where, and the exponential moving standard
  deviation.
- The exponential moving standard deviation is left out on purpose: Java seeds a run that
  starts inside a bucket with the square of the previous result as the variance, which is
  not the variance it computed, so Java's own incremental results differ in the last bits
  from a static recompute and fail the consistency checker as it stands.
- Within a bucket, non-null timestamps must not decrease; the whole bucket is checked on
  every update. Java checks only the rows added (and re-stamped) in one update, so a
  decrease across updates fails here with Java's message where Java computes something
  undefined.
- `fixtures/java_update_by.json` is recorded from Java 42.9 by
  `fixtures/record_java_update_by.py` (sections `static`, `long`, `timed`, `ticking`) and
  compared bit for bit by `corpus.rs`; `oracle_corpus.rs` replays the oracle scenarios that
  only need `update_by`, comparing every result column but those of the `unported!`
  operators.
- The gRPC handler is not part of this branch (the table service did not exist when the
  work started).
