## Scope

Extract formula strings used in the Java engine tests, the Python server tests and the docs into a corpus file, each with the input schema it needs. Run each against the oracle and record the result or the error. Classify each as in the accepted subset (no arbitrary Java method calls or object construction) or outside it. This task changes the protected `oracle/` path, so the orchestrator labels its pull request.

## Gate

```bash
oracle/bin/harness formulas --record --url "$JAVA_URL"
```

`$JAVA_URL` is described in `tasks/README.md`. Recording twice must change nothing: the second run prints `0 outcomes changed`.

## Notes

- 6309 cases in `oracle/corpus/formulas/`: 4457 from the systematic grid (`grid-*`), 1852 extracted (`java-parser`, `java-formula-column`, `java-engine`, `py-server`, `docs-python`). `oracle/README.md`, "Formula corpus", describes the format and the commands.
- Besides `oracle/corpus/formulas/` this adds `oracle/harness/formulas/`, `oracle/tests/test_formulas.py`, the `formulas` subcommand in `oracle/harness/__main__.py` and a section in `oracle/README.md`.
- The gates of tasks 5.2 to 5.5 name `formulas --check accept-reject | values | functions | arrays`; those checks exist. Each takes the accepted cases that run directly against a fixture; `chains`, `outside` and `minimal` are further checks.
- A formula that names something outside its input table (a query scope variable, a Python or Groovy function, a test class) is left out, as are formulas of `TestQueryLanguageParser` that need a boxed, vector or object variable. `--generate` prints the counts.
- 41 extracted cases have a `setup` that Java itself refuses over gRPC (method calls the expression validator forbids, time zone names 42.9 no longer parses). They are kept with their recorded error and skipped on replay.
