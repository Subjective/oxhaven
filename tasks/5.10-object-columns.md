## Scope

In order, measuring the formula gate after each:

1. A general `Object` column of one static class (option 3 of the 5.9 notes): `deephaven:type` `java.lang.Object`, cells kept exactly as the class they are; a column that would mix classes is refused by name. With it `java.time.DayOfWeek` (`dayOfWeek()`, `LocalDate#getDayOfWeek()`), a bare `null` column, `(java.lang.Object) B` and the other cases the 5.9 notes attribute to it. The wire form is what Java sends, probed first.
2. `boolean[]`, and the element-wise array comparisons of the type checker and evaluator.
3. Object creation (`new ...`) as an expression node, for the classes the corpus uses and Java's validator allows.
4. If there is room: sorting and match filters on `LocalDate`, `LocalTime`, `Duration` and `ZonedDateTime`, which Java sorts (`ZoneId` and `Period` stay refused, as in Java).

Not in scope: a column whose cells mix classes (option 2 of the 5.9 notes).

## Notes

Started from main at `2a9202c`.

### Contract changes

All in `crates/oxhaven-contracts/src/schema.rs`, additive (`ColumnType` is `#[non_exhaustive]`); `expr.rs` did not change.

| Variant | Arrow storage | What Java 42.9 sends (probed) |
| --- | --- | --- |
| `DayOfWeek` | `Int8`, `getValue()` (Monday 1) | `Utf8` of the name, `deephaven:type` `java.time.DayOfWeek`, sortable |
| `Object(Option<Box<ColumnType>>)`, with `ColumnType::object` | the class's own storage; `None` (nulls alone) is `Utf8` | `Utf8` of `toString`, `deephaven:type` `java.lang.Object`, no `isSortable` |
| `PrimitiveBoolean` | `Boolean`; only ever the element of `Array`, so `Array(PrimitiveBoolean)` is `boolean[]` | `list<bool>`, `deephaven:type` `boolean[]`, `componentType` `boolean`, no `isSortable` |

An `Object` column holds one class, kept exactly: a boxed primitive keeps the value Java reserves for null as a value (`(Object) I` of a null `int` is `"-2147483648"` in Java, probed), and only the validity says null. A formula that would mix classes (`c ? (Object) 1 : (Object) "a"`, `new Object[]{1, "a"}`) is refused by name. `Object[]` has no `componentType`, as Java sends it (`BarrageUtil#isTypeNativelySupported`).

No `Expr` node was added for `new`: the parser already writes object and array creation as a `Call` of a name no formula can spell (`parse::NEW`), and the type checker knows those names; a node would change every match of `Expr` for nothing the checker lacks.

### Corpus cases

The formula gate, each time against a freshly started server: 48 distinct differing cases on `2a9202c` (accept-reject 3, values 3, functions 1, arrays 7, chains 18, outside 19), 31 after the `Object` column and `DayOfWeek`, 25 after `boolean[]`, 24 after `new Object[]`, 24 after merging main. None newly differs at any step. `cargo test -p oxhaven-expr --test formulas`: 0 corpus cases differ.

What formulas do now: `null` alone and `true ? null : null` (a column of nulls); `(Object) x` and `(java.lang.Object) x` of a primitive, `Boolean`, `String`, `Instant`, `LocalDate`, `LocalTime` or `DayOfWeek`; `==` and `!=` of objects as `eq(Object, Object)` (two classes never equal, `Double#equals` for floating point), concatenation, `isNull`; `(int)`, `(long)`, `(float)`, `(double)` of an object (`intCast(Object)`), and a cast back to its class, failing with `ClassCastException` for a value of another class; `?:` with an `Object` branch; `dayOfWeek(Instant, ZoneId)`, `dayOfWeek(ZonedDateTime)`, `dayOfWeek(LocalDate)`, `LocalDate#getDayOfWeek()`; `==`, `<`, `<=`, `>`, `>=` of a numeric array with an array or a number (`eqArray`, `lessArray` and relatives) into a `boolean[]`; `new Object[]{...}`.

### Refusals left

- The 24 cases still differing: `String.format` (2, and a chain behind one), `randomDouble`, `today()` (and a chain behind it), `String.split` (2), `isBusinessDay`, casts to `CharSequence` (2) and `Double` (2), `ColumnDefinition.ColumnType.Normal` (2), `Integer.class`, `String.class`, `new String(char[], int, int)` (2), `new Integer[5]` (a `java.lang.Integer[]`, a boxed class no column type is), `new int[4][2]`, `Z2_` (a column array of `Boolean`, sent as strings), `nanosToSeconds(Timestamp - '2000-01-01T00:00:00 ET')` (refused as `function nanosToSeconds()`, uncovered now that its setup runs), and `C == \`2\` ? 2 : C`, an `Object` column of `Integer` and `String`, refused as a column of two classes by design.
- Ordering a `DayOfWeek` (`<`, `compareTo`), which Java does; methods of a `DayOfWeek` (`getValue()` is refused by Java's validator, probed) and of an `Object` (`toString()`, `equals`, `hashCode`).
- Element-wise comparisons of vectors, and of arrays of `Boolean`, `String` or objects; `!=` of arrays, which Java also refuses.
- The engine was not changed: sorting, match filters, joins and aggregations on `Object`, `DayOfWeek` and `boolean[]` columns fail or are refused as for any type they do not know. Java sorts a `DayOfWeek` column (probed) and refuses to sort an `Object` column (probed).
- A range (`DiscretizedRangeEqual`) is held as a `double[]` in the checker (5.8); comparing one is refused by name so that it is not compared as an array.

### For the owner

- The three contract variants above.
- Piece 4 of the scope (sort and match filters on `LocalDate`, `LocalTime`, `Duration`, `ZonedDateTime`) was not started.

### Handover

What is left, in the order of the scope:

1. Object creation still refused: `new int[n][m]` (the parser refuses arrays of arrays: `parse/mod.rs`, `creation`), `new String(char[], int, int)` (`types/mod.rs`, `call_of`, beside `NEW_STRING`), `new Integer[n]` (needs a boxed-`Integer` element, which is no column type; `Object(Int)` names `java.lang.Object`).
2. Sort and match filters on `LocalDate`, `LocalTime`, `Duration`, `ZonedDateTime` and now `DayOfWeek` (by its number), in the engine (`SortOperation`, `MatchFilter.ColumnTypeConvertorFactory`); `ZoneId`, `Period` and `Object` stay refused, as in Java.
