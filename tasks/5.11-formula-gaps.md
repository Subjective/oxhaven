## Scope

Small gaps found by earlier tasks, each probed on Java first:

1. The instant parser panics with an arithmetic overflow on all-digit text such as `9309340999` (7.4.3, "For the owner", item 1); also unchecked arithmetic in the neighbouring date, time, duration and period parsers.
2. Four filter formulas Java evaluates and this crate refuses (4.22, "Differences from Java found"): `D == 2024-03-10` on a `LocalDate`, a `LocalDate` against a `String`, `Dur < null`, and `P == 'P1Y'`. Port the Java rule that makes each legal rather than four special cases.
3. The remaining `new` forms (5.10, "Handover", item 1): `new int[n][m]` and the other element types, `new String(char[], int, int)`, `new Integer[n]` and the other boxed arrays. A form that needs a column type the contracts lack is refused by name.
4. Size-only calls (`T_[i-1].size()`) on a column array of a vector of `Boolean` or `Instant` (4.23 refuses them wholesale).

Not in scope: changes to `crates/oxhaven-contracts`, `PARITY.md`, `oracle/replay-baseline.json` or the gate scripts.
