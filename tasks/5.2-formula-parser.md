## Scope

The full accepted grammar: everything in task 3.1 plus ternaries, casts, method-style and function calls to the built-in library, string and char literals with Java escapes, backtick strings, time literals, bitwise operators, `in`-style helpers the Java parser rewrites, and implicit conversions. Type checking follows `QueryLanguageParser`'s promotion rules. Formulas outside the subset are rejected with an error naming the construct.

## Gate

```bash
cargo test -p oxhaven-expr parse types && oracle/bin/harness formulas --check accept-reject --url "$OXHAVEN_URL"
```

`$OXHAVEN_URL` and `$JAVA_URL` are described in `tasks/README.md`. The `formulas` command and its checks are described in `oracle/README.md` ("Formula corpus").

## Notes

Done together with 5.3 on branch `task/5.2-formula-language`, before 5.1 landed.

- Accepted beyond 3.1: `?:`, casts to the seven primitive types and to `Boolean`, `String` and `Instant` (`(boolean) x` included), `& | ^` on integral and on Boolean operands, `+` with a `String` operand, typed `null` in a cast, a ternary branch and string concatenation, time literals, hexadecimal floating literals, octal literals, `\uXXXX` and `\'` escapes, and these `String` methods: `length()`, `isEmpty()`, `charAt(int)`, `contains(String)`, `startsWith(String)`, `endsWith(String)`, `indexOf(String)`, `substring(int)`, `substring(int, int)`, `toUpperCase()`, `toLowerCase()`, `trim()`, `equals(String)`, `compareTo(String)`, `concat(String)`.
- Every function call is `Expr::Call` and refused by the checker as `function name()`: the function library is task 5.4. Row variables and column arrays are refused by name: task 5.5.
- `QueryLanguageParser` has no `in` rewrites. `in`, `not in` and `icase in` are match filters of `WhereFilterFactory`, so they are not formulas and are a syntax error here.
- Instant arithmetic (`T + 1`, `T - T`) goes through the function library in Java, so it is refused by name.
- Time literals accepted: `yyyy-MM-ddTHH:mm[:ss[.f]] UTC`, the same ending in `Z`, `yyyy-MM-dd UTC` and `yyyy-MM-ddT UTC`. Other zones, durations, periods and local times are refused by name.
- Java refuses `-x` for a `byte`, `short` or `char` operand (an assertion in `QueryLanguageParser#visit(UnaryExpr)`). Task 3.1 typed it as `int`; it is a type error now.
- Refused although Java accepts them, each by name: a float literal ending in uppercase `F` (Java types it `double`), `\s`, a subnormal or over-long hexadecimal floating literal, casts to boxed types and `Object`, `null` beside a reference operand of `&` or `<`, `null == null`, a bare `null` column, static calls and field access, other `String` methods and overloads, methods of `Boolean` and `Instant`. The full list for the recorded formulas is `crates/oxhaven-expr/tests/data/java_formulas_refused.txt`.
- Check against Java: `tests/data/java_formulas.json` holds what Deephaven 42.9 did with the 1374 formulas of `java_formulas.txt`, recorded by `record_java_formulas.py` from a server started with `oracle/bin/start-java.sh`. The test `recorded` compares every one: 1243 agree, 0 differ, 127 are refused by name, 4 are match filters.
- The `oracle/bin/harness formulas` part of the gate was not run: the command does not exist yet.
