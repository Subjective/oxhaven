## Notes

The row variables `i`, `ii` and `k` were already evaluated (3.4, 5.3). This task adds column arrays.

- `Col_[i]`, `Col_[ii]` and `Col_[i ± n]` with `n` in decimal digits, reached from the top of a formula through binary operators, parentheses and `?:`, become a shifted column as in `ShiftedColumnsFactory`: `select/arrays.rs` adds the column, computes the rewritten formula over it and drops it. The column list is split at the first such column as `AnalyzerContext#applyShiftsAndRemainingColumns` splits it. `where` adds the shifted columns of all its filters at once (`ShiftedColumnsFactory#where`).
- The rewritten formula reads only its own row, so it is accepted on a refreshing table. A row whose neighbour was added, removed or modified is reported as modified in the shifted column, with bulk row set operations, as the listener of `ShiftedColumnOperation` does.
- Every other use (`Col_[3]`, `Col_[i - Other]`, `isNull(Col_[i - 1])`, `Col_.size()`, `sum(Col_)`, `Col_`) is evaluated by the formula in `eval/arrays.rs` over the table's rows: an index reads only the rows it names, a part made of column arrays and literals alone is evaluated once, and anything else reads the column once per evaluation. An index that is null or not a row gives null. On a refreshing table that is not a blink table such a formula is refused as in Java, except in a filter, which Java asks again only about added and modified rows.
- A result with shifted columns is append-only when the parent is and no column is read ahead, a blink table when the parent is, and never add-only. The table between the steps has no attributes, so `Col_[i - 1] + i` is refused on an append-only table too.
- A query scope variable in an index (`X_[i - n]`) is replaced by its value in `oxhaven-server`'s `ScopedCompiler`; as in Java such an index is not a fixed distance.

Refused by name:

- `ShiftedColumnOperation#computeDirtyModifiedRowSetInPositionSpace`: shifted columns at two different distances, neither zero, on a refreshing table (`X_[i - 1] + X_[i + 1]`, `X_[i - 1] + X_[i - 2]`). Java gives the positions it computed for the first distance to `RowSet#invert` as row keys. On Java 42.9 `update("P = X_[i-1] + X_[i-2]")` of a keyed input table keeps old values in the rows after a replaced row, and `update_view` of the same formula shows the new ones.
- `SelectAndViewAnalyzer.AnalyzerContext#getPublishedColumnSources`: `select` with a shifted column on a static table whose result gets new row keys. On Java 42.9 `empty_table(6).update("X = i * 10").where("X != 20").select("Y = X_[i-1]")` has the 20 of the row that `where` dropped.
  Task 5.6 narrowed the refusal to the columns that read the table: `select(["W = X + 1", "Y = W_[i-1]"])` of that table is right in Java and computed, while `select(["W = X + 1", "Y = X_[i-1]"])` is wrong in Java and refused.
- `ShiftedColumnOperation#addShiftedColumns`: a shifted column on a table that has a column of the shifted column's name (`__X_Shifted_Minus_1__`). Java 42.9 computes the formula and drops the table's column from the result.
- `ShiftedColumnsFactory#parseForConstantArrayAccessAttributes`: an offset in another base or with `_` separators, or beyond the `long` range.
- `ShiftedColumnsFactory#getShiftedColumnDefinitions`: a column array indexed through parentheses (`(X_)[i - 1]`), which the expression tree cannot tell from `X_[i - 1]`.
- `ColumnVectors#of`: a formula whose value is the column array of a `Boolean` or `Instant` column, which Java sends as a list of strings; more than `i32::MAX` list elements in one evaluation; and the column array of a column of vectors or arrays (a shifted column of one works).
- `DhFormulaColumn#generateAppropriateGetMethod` (already there): `lazy_update` with a column array that is not rewritten.

Gate: `cargo test -p oxhaven-expr arrays` passes. `oracle/bin/harness formulas --check arrays` went from 95 differing cases of 279 to 32 of 340, so the command still exits 1. The 32 are all formulas Java computes and this server refuses: 19 time literals with a zone name or `now()` next to a row variable, 10 arithmetic and comparisons of arrays (`myIntArray + 1`, and the column array case `I2_ + 1`), `randomDouble`, `(int[])(null)`, and `Z2_`, the column array of a `Boolean` column, refused as above. Three cases with a list result are not compared by the harness's rules. The formula corpus gained 75 cases (`grid-array/extra.44` to `.96`, `grid-where/extra.109` to `.130`); the scenarios `column_arrays`, `ticking_column_arrays` and the script scenario `table_column_arrays` are recorded from Java 42.9 and clean.

`oracle/harness/fuzz_wide.py` does not generate these formulas: a generated `select` would meet the refusal above, and the generator's digests are pinned.
