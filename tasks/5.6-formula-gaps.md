## Scope

The formulas that Java computes and `oracle/bin/harness formulas --check arrays` reported as refused when 5.5 merged: time literals with a zone name, durations and periods added to an `Instant`, `now()`, the random numbers, operators on vectors and arrays, and a null cast to an array type. Also the static `select` that 5.5 refuses although Java computes it.

## Notes

Everything below was seen on Java 42.9.

- A time literal is tried as Java tries it: an instant, then a period, then a duration. An instant may name a zone after a space: `UTC`, `GMT`, a region name with a `/`, or one of the aliases of `default_time_zone_aliases.csv` (`ET`, `CT`, `MT`, `PT`, `HK`, `JP`, `LON`); `EST`, `NY` and `et` are no zones in Java either. A time that a clock change skips is moved later by the length of the gap, and one that occurs twice is the earlier (`LocalDateTime#atZone`). The zone rules are those of `chrono-tz`.
- A duration or period literal is a value only where it is added to or subtracted from an `Instant`, alone or multiplied or divided by a whole number (`T + 'PT1m' * ii`, `T - 'P1d'`). A period is days and weeks only; a null on either side gives null; an overflow and a division by zero fail when read, as in Java.
- `now()` and `nowSystem()` read the system clock once per row. `random()`, `randomBool()`, `randomInt`, `randomLong`, `randomFloat`, `randomDouble` and `randomGaussian` with two numbers have Java's types, ranges and failures (`randomInt(5, 5)`, `randomDouble(1, 1)`); their generator is not Java's. A formula that calls one of them is not evaluated once for the whole table, as a formula of literals is.
- `+ - * / %` with a vector or an array on either side is that operator on each element, with a single value beside an array used for every element. The result is an array of the type the operator gives the elements, for vectors as well. Arrays of different lengths and a null array fail when read; `!=`, a unary minus, `?:` on the result and a cast to another element type do not compile, as in Java.
- `(int[]) null`, and the same for the other primitive types, `String` and `Instant` in any number of dimensions, is a null array; a cast of an array to its own type is the array.
- A static `select` that gives its result new row keys computes a shifted column when that column and every column after it read only columns that the formulas of the same call define, and no `k`: `select(["W = X + 1", "Y = W_[i-1]", "Z = Y_[i+1] + W"])`. Those are the cases Java computes rightly; the result has new row keys there too.

What the harness compares for `now()` and the random numbers: `oracle/harness/formulas/tags.py` marks a formula that calls `now...`, `random...`, `today...` or the clock as `nondeterministic`, and `compare.py` compares only the type of such an outcome, and a failure against a failure. `crates/oxhaven-expr/tests/formulas/recorded.rs` does the same.

Refused by name:

- `QueryLanguageFunctionUtils#eqArray`, `#lessArray`, `#greaterArray`, `#lessEqualsArray`, `#greaterEqualsArray`: a comparison with a vector or an array (`myIntArray == 1`). Java's column is a `boolean[]`. `ColumnType::Array(Boolean)` is `java.lang.Boolean[]` to a client, and nothing in the expression crate takes an array of `Boolean`, so the result could be neither a column nor an argument. Computing these needs a column type for `boolean[]` in `oxhaven-contracts`, which this task does not change. These are six of the gate's seven cases.
- `QueryLanguageFunctionUtils#binaryAndArray`, `#binaryOrArray`, `#xorArray`: `& | ^` with an array.
- `QueryLanguageFunctionUtils#plus(Object, String)`: an array and a `String`, which is the array's identity hash in Java.
- `DateTimeUtils#parseDuration`, `#parsePeriod`: a duration or period as the value of a formula or as an argument (`'PT24h'`, `plus(T, 'PT1m')`), since no column type is one; a period with years or months, which Java adds to an `Instant` with an exception; and a duration written `PT1:30:00`.
- `TimeZoneAliases#zoneId`: a zone written as an offset (`'2024-01-01T00:00:00 +01:00'`, `UTC+1`).
- `Random#randomDouble(double, double, int)` and the other forms with a size, whose result is an array.
- `SelectAndViewAnalyzer.AnalyzerContext#getPublishedColumnSources` (narrowed): the static `select` above when the shifted column or a later one reads a column of the table or `k`. Java reads the table's columns by the new row keys: with `t = empty_table(6).update(["X = i * 10", "U = i"]).where("X != 20")`, `t.select(["W = X + 1", "Y = W_[i-1] + X"])`, a later `Z = X * 2`, `Z = X_[i-1]` and `sum(X_)` have values of other rows. `k` there is the new row key in Java, which is right and still refused here.

Gate: `cargo test -p oxhaven-expr gaps` passes. `oracle/bin/harness formulas --check arrays` went from 32 differing cases of 340 to 7, and still exits 1. The seven are the six comparisons of arrays above (`java-parser/L1267` to `L1287`) and `Z2_` (`grid-array/extra.85`), the column array of a `Boolean` column that 5.5 refuses. Eight cases with an array result have the recorded type and values and are counted as uncompared by the harness's rules.

The other groups of the same command, in differing cases before and after: `minimal` 0 and 0 of 2958, `accept-reject` and `values` 47 and 42 of 4257, `functions` 43 and 14 of 352, `chains` 350 and 120 of 1099, `outside` 113 and 113 of 336. What is left there has other causes: functions that are not ported (`parseInstant`, `toZonedDateTime`, `today`), literals whose type is no column type (`'PT24h'`, `'2020-01-01'`, `'ET'`), and the null literal as an operand.

`ops/update_by/fixtures/java_update_by_formula.json` had `sum(I * 2)`, `sum(I + L2)` and `sum(D * F)` in its section of refused rolling formulas; with the operators on vectors they are answered, and their recorded results moved to the section that is compared.

Not done, static calls on `java.lang.Math`: `Math.sin(D)` is computed by Java in a console script and refused by Java in a table operation sent over gRPC (`ColumnExpressionValidator`), which is why the formula corpus records those cases as failing; `String.valueOf`, `Long.toString`, `Math.PI` and `Integer.MAX_VALUE` are computed on both paths. Here every static call is refused on both. Java's `Math` methods take the null values as numbers: an argument is widened as `doubleCast` widens it, so `Math.sin(I)` of a null `int` is `sin(NULL_DOUBLE)`, and a result is null only when it is the null value of its type (`Math.abs(I)`, `Math.floor(D)`). Computing them takes the methods with Java's overloads in the expression crate, without the null handling of the functions of the same names, and a refusal in the server's validation of gRPC requests that the console does not apply.
