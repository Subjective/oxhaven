## Scope

The formulas that Java computes and the groups of `oracle/bin/harness formulas --check <group>` reported as refused when 5.6 merged: static calls (`String.valueOf`, `Long.toString`, `DateTimeUtils.now()`, `java.lang.Math`), a null literal as an operand, object and array creation, the time functions that were never ported, and the literals whose type is no column type where they are arguments. A formula whose result column would have a type that is no column type stays refused; so do the Boolean column array `Z2_` and the comparisons of arrays.

## Gate

```bash
cargo test -p oxhaven-expr --test formulas && for group in minimal accept-reject values functions arrays chains outside; do oracle/bin/harness formulas --check $group --url "$OXHAVEN_URL"; done
```

`$OXHAVEN_URL` and `$JAVA_URL` are described in `tasks/README.md`. The `formulas` command and its checks are described in `oracle/README.md` ("Formula corpus"). Every group but `minimal` still exits 1: the counts below are what is left.

### What Java does

- A static method of a class of `java.lang` (`Math`, `StrictMath`, `Integer`, `Long`, `Float`, `Double`, `Boolean`, `Character`, `String.valueOf`) is the raw Java method on the value the generated code holds: nothing looks for null, so `Math.abs(I)` of a null `int` is -2147483648, which is null again, `Math.sqrt(I)` is NaN and `Integer.toString(I)` is `"-2147483648"`. An argument of another primitive type is converted by the cast function of the parameter's type, which keeps null (`Integer.toString(B)` of a null `byte` is `"-2147483648"`). A result is null only where it is the null value of its type. A parameter takes an argument when binary promotion of the two types gives the parameter's (`QueryLanguageParser#dhqlIsAssignableFrom`): `int` takes `byte`, `short`, `char` and `int`; `short` takes only `short`.
- A method of a class of the default static imports called through the class (`DateTimeUtils.now()`, `io.deephaven.function.Numeric.abs(I)`) is the function a formula calls without the class. `Math.PI`, `Math.E`, `Boolean.TRUE`, `Boolean.FALSE` and `Calendar.JANUARY` are constants.
- A client is refused the methods of `Math` and `StrictMath` with `INVALID_ARGUMENT` and `User expressions are not permitted to use static method sin(double) on class java.lang.Math`; the console computes them. `oxhaven_expr::RequestCompiler` is the compiler of the table operations of a client and refuses them with that text; `Compiler` computes them, and the console uses it. The recorded cases that fail in Java this way still fail.
- The null literal is an operand where Java finds one method for it: `&`, `|` and `^` beside a `Boolean` or another null give null (`false & null` too); `<`, `<=`, `>` and `>=` beside a `String`, `Boolean` or `Instant` order null first; `null == null` is true; `null - Instant` is a null `long`. Arithmetic with null, `null < null`, `!null` and `-null` fail in Java and are type errors here. `null` alone is a column of `Object`.
- `new int[]{a, b}`: javac converts each element by assignment, which widens without looking for null (`new int[]{B}` of a null `byte` holds -128, `new double[]{I}` holds -2147483648.0) and takes an `int` literal that fits for `byte`, `short` and `char`. An element that holds the null value of the element type is a null element. `new int[]{}` and `new int[]{null}` do not compile. `new int[3]` is zeros and `new String[2]` nulls; the length must be a literal from 1 to 1024 here.
- `new Integer(x)` and the other boxed constructors choose the constructor and convert the argument as for a static method, and the formula's value is the primitive: `new Integer(B)` keeps null, `new Integer(L)` and `new Short(B)` do not compile. `new String(s)` and `new Boolean(z)` throw for null. A client may construct these classes and not `Object`, `StringBuilder` or `ArrayList`.
- `parseInstant(String)` reads what an instant literal spells and also a whole number, which is seconds, milliseconds, microseconds or nanoseconds by its size; it throws for null and for other text, and `parseInstantQuiet` is null for both and for text of one character. `epochSeconds` and `epochMillis` round toward the past, `epochMicros` toward the epoch.
- `plus`, `minus`, `lowerBin` and `upperBin` take a duration (and `plus` and `minus` a period) where the formula spells it as a literal or as `parseDuration` of a literal.
- `secondOfDay`, `minuteOfDay`, `hourOfDay`, `millisOfDay` and `nanosOfDay` of an instant, a zone and a flag count from midnight on the clock when the flag is true and from the instant the day began when it is false; the two differ on a day the clocks change. `year`, `yearOfCentury`, `monthOfYear`, `dayOfYear`, `dayOfMonth`, `dayOfWeekValue`, `minuteOfHour`, `secondOfMinute`, `millisOfSecond`, `microsOfSecond` and `nanosOfSecond` take an instant and a zone. The zone is a literal (`'ET'`) or `timeZone` or `parseTimeZone` of a string literal.
- `Instant.getEpochSecond()`, `.toEpochMilli()` and `.toString()`, `String.hashCode()` and `String.replace` with two `char` or two `String` arguments throw for a null value. A hash of -2147483648 is null in the column.
- `parseDouble` and `parseFloat` are null for null and read Java's grammar, the hexadecimal form included (`0x1p3`).
- `compareTo` of two numbers puts null first and NaN last.
- `median`, `absAvg`, `avg`, `sum`, `product`, `std`, `var`, `count`, `countDistinct`, `first` and `last` with one or more numbers of one type are the function of an array of them.

### Refused by name

Each is `unsupported in formulas: <text>`, or a failure when read where the value decides.

- `static method call C.m()` for a method not listed in `functions/statics.rs`, among them `Math.cbrt`, `Math.hypot`, the `*Exact` methods, `Character.isDigit` and `isLetter`, `String.format` and `String.join`; `static method call C.m() with these arguments` and `with a null literal as an argument` for an overload not ported.
- `constructor new C()` for a class that is not boxed or `String`; `constructor new C() with these arguments` for `new Float(double)`, which narrows the null `double` to `-Infinity`, and `new String(char[])`.
- `array creation new T[]` for `boolean`, the boxed classes and other objects; `array creation new T[][], of arrays`; `array creation new T[n] with a length that is not a literal from 1 to 1024`.
- `null literal as an operand of <op>` where the other side is not a `Boolean`, `String` or `Instant`; `null literal outside ==, !=, ?:, a cast and string concatenation`; `null in both branches of ?:`.
- `function f() with a time zone that is not a literal`, `time zone 'X'` for a zone Java knows and this server does not (an offset, `UTC+1`), `function f() of a value of type T` for a field of a value that is no `Instant`.
- `function compareTo() of a long and a floating point number`, which has rules of its own in Java (`QueryLanguageFunctionUtils#compareTo(long, double)`), and `function compareTo()` of values that are not numbers.
- `function parseTimeZone()`, `function parseDuration()` and the other makers of values whose type no column has, where the value is not an argument of a function above.
- When read: `parseInstant of "...", a spelling of an instant this server does not read (io.deephaven.time.DateTimeUtils#parseInstant)` for a date and time without a zone that Java reads another way, or with an offset. `parseInstantQuiet` fails the same way where Java may return null or an instant.

### Contract gaps

- `oxhaven_contracts::expr::Expr` has no node for object or array creation. The parser emits a call whose name starts with `new ` (`new Integer`, `new int[]`, `new int[n]`), which no formula can write, and the type checker reads it.
- No column type for `Duration`, `Period`, `ZoneId`, `ZonedDateTime`, `boolean[]` or `Object`. 111 of the 123 cases left need one of these or `LocalDate` or `LocalTime`.
- `ColumnType::LocalDate` and `ColumnType::LocalTime` came to main with the Parquet reader while this task was in review. No formula makes a value of either yet: the literals (`'2020-01-01'`, `'12:30:45'`), `parseLocalDate`, `parseLocalTime`, `epochDaysToLocalDate`, `LocalDate.ofEpochDay` and `LocalTime.of` are the next step, for the 23 cases whose result is one of the two and the cases whose setup has one. `Literal` has no variant for either.

No file under `oracle/` changed and no case was recorded.
