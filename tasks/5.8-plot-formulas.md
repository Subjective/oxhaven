### The range of a histogram

`functions/range.rs`. The arithmetic is the Java class's on the values as the generated code holds them: the arguments are converted as a cast converts them, nothing looks for null, and a result is null where it is the value Java reserves for null. `index` is null for a value that is not finite (the null `double` among them) or outside the range, and the maximum belongs to the last bin. A range of no bins (`n = 0`) has an infinite or NaN width and one without width (`min == max`) a width of zero; Java computes with them and so does this, to the same cells.

No column type of the contracts holds an object of a class, so a range is a `double[]` of four elements: minimum, maximum, width, and a NaN of a payload no computation makes, by which the methods know it. What follows from that, all of it in cases the plugin does not reach:

- a client that fetches the column is told `double[]` and sent the four numbers; Java tells it the class and sends `...DiscretizedRangeEqual@<identity hash>`;
- `equals`, `==`, `hashCode` and `toString` of a range, a cast to the class or to its interface, and `select_distinct`, `sort` and an aggregation by the column are refused (Java compares identities);
- a method of a range called on another `double[]` column compiles and fails when a row is read.

`tests/data/java_range.json` holds what Java answered for 297 formulas (`record_java_range.py`): 288 agree and 9 are refused by name (`java_range_refused.txt`).

### `new Random(seed).nextInt(bound)`

`functions/random.rs`: the generator of `java.util.Random`, for the two calls together. A seed of `byte`, `short`, `char`, `int` or `long` (a null one is the null `long`, whose low 48 bits are those of zero), a bound that widens to `int`; a bound that is not positive, null among them, fails as in Java (`IllegalArgumentException: bound must be positive`). `tests/data/java_random.json`: 64 formulas, 57 agree, 7 are refused by name.

Refused: `new Random()` (`java.util.Random#Random()`: the seed is the clock), a `Random` as the value of a column (Java keeps the object, and it gives another number each time it is asked), and the other methods (`nextInt()`, `nextInt(int, int)`, `nextLong`, `nextDouble`, `nextBoolean`, `nextGaussian`), each by `java.util.Random#<method>`.

### A client's formula

Java's validator refuses a table operation of a client that makes either object, and so does `RequestCompiler`, with Java's text: `User expressions are not permitted to instantiate class java.util.Random(long)`, `... class io.deephaven.plot.datasets.histogram.DiscretizedRangeEqual(double, double, int)`, `... to use method index(double) on class ...`. Only the script session's own operations compute them.

### An `Instant` of the query scope

`app/scope.rs` (`FormulaValue::Instant`), `console/python/mod.rs` (`java_instant`). Java gave the same answer for the variable and for the instant literal of the same time in each of 30 formulas, so the variable is compiled as the literal. What is refused for the literal is refused for the variable: the methods of `Instant` and the functions that are not ported. `(long)` of the variable is refused when the formula is compiled; Java compiles it and fails on the first row (`ClassCastException`).

Not done: the other Java time objects of the package as variables (`ZonedDateTime`, `LocalDate`, `LocalTime`, `Duration`, `Period`, `ZoneId`), which Java computes with and no column type holds. A Python `datetime`, `numpy.datetime64` or `pandas.Timestamp` is an `org.jpy.PyObject` in Java too and stays refused.

### Items of a Python list and dict

`app/scope.rs` (`FormulaValue::Items`, `item_function`), `console/python/udf.rs` (`bind_item`), `python/_oxhaven_udf.py` (`item_reader`). `docs/CONSOLE.md` ("The query scope") has the rules and what is refused. `(cast) name[index]` is compiled as a call of a function of the language that only the script session's compiler has, and the item is read from the Python object when a row is computed, under the interpreter lock, a chunk at a time, as a Python function is called.

### For the owner's ruling

Java behaviour that is unsafe, not deterministic or looks like a defect. None was decided here: each is reproduced or refused, as listed.

1. **An `Instant` variable outside the years 1677 to 2262.** Java converts it to nanoseconds where the formula uses it (`DateTimeUtils#epochNanos`): the year 2300 fails (`DateTimeOverflowException`), and the year 1600 silently becomes 2184-07-20 as a column while `early.getEpochSecond()` reads the true time and `T < late` compiles and compares. Refused here, naming the method.
2. **A range sent to a client** is its identity text in Java, which differs from run to run; here it is the `double[]`. Equality of two ranges is identity in Java; refused here.
3. **`(int)` of an item beyond 32 bits** keeps the low 32 bits without a failure in Java: `2**40` is 0 and `2**31` is null. Reproduced.
4. **A null index or key** is the number Java reserves for null: `list[NULL_INT]` fails with `IndexError`, and a dict that has the key `-2147483648` gives its item for a null `int` column cell. Reproduced.
5. **A range of no bins or no width** has bins of infinite, NaN or zero width in Java, and `index` of a value in it is what the cast of NaN or infinity to `long` gives. Reproduced.
6. **`java.util.Random` kept in a column** and **`new Random()`**: not deterministic. Refused.
7. **A Python global named like a constant of the language** (`from deephaven.constants import NULL_INT` in the console) replaces the constant in every formula of the session, a client's too, and is a boxed number there: `new Random(NULL_INT)` is seeded with -2147483648 where the constant gives the null `long`. This server refuses a variable that holds the null value of its type, as before this task.

### Contracts

Nothing in `crates/oxhaven-contracts` changed. What would be the clean form and is not there:

- a column type for an object of a Java class that is not a value of another column type (`DiscretizedRangeEqual`, `java.util.Random`, `org.jpy.PyObject`, the time objects above). With it the range would not be a marked `double[]`, a client would be told the class, and a `Random` or an item without a cast could be a column;
- object creation as a node of `Expr`: it is a call of a function named `new <Class>`, and an item of a variable is a call of a function named `(cast) name[]`, a name no formula can spell.
