## Scope

The column types the formula corpus still needs and the contracts do not have: `Duration`, `Period`, `ZoneId`, `ZonedDateTime`, a general `Object` column and `boolean[]`; the literals and makers of `LocalDate` and `LocalTime`, which are column types already; and object creation as a node of `Expr`. Each type is carried through the contracts, the column sources, the engine, the type checker and evaluator, and the schema and cells a client is sent, which must be what Java sends (probed on the Java reference before each type is decided). The order of the work is the number of corpus cases each type unlocks.

A general `Object` column is done only if it fits the storage of the other columns; otherwise its design options are written down here and it is left.

## Notes

### Contract changes

`ColumnType` gains four variants, each with its Arrow storage (`crates/oxhaven-contracts/src/schema.rs`); nothing else in the contracts changed, and `expr.rs` did not change:

| Variant | Arrow storage here | What Java 42.9 sends (probed) |
| --- | --- | --- |
| `Duration` | `Duration(Nanosecond)` | `duration[ns]`, `deephaven:type` `java.time.Duration`, sortable |
| `Period` | `Struct{years, months, days: Int32}` | `Interval(YearMonth)` of `getYears() * 12 + getMonths()` (the days are dropped: `DefaultChunkWriterFactory#intervalFromPeriod`), `java.time.Period`, not sortable |
| `ZoneId` | `Utf8`, the id | `Utf8` of `ZoneId#getId`, `java.time.ZoneId`, not sortable |
| `ZonedDateTime` | `Struct{instant: Timestamp(ns, UTC), zone: Utf8}` | `timestamp[ns, tz=UTC]` of the instant (the zone is dropped), `java.time.ZonedDateTime`, sortable |

A period and a zoned date time are structs so that a formula keeps what Java keeps (the days of a period, the zone of a zoned date time); the server converts them to Java's wire form (`wire_columns.rs`). An upload of these types is still refused: `column_type_for_java_name` was not extended.

### Corpus cases

The formula gate, against a freshly started server each time: 123 distinct differing cases on `11133e6` (minimal 0, accept-reject 15, values 15, functions 5, arrays 7, chains 68, outside 28), 48 after (0, 3, 3, 1, 7, 18, 19). None newly differs. The 75 cases, by what refused them before: `ZoneId` (`timeZone`, `parseTimeZone`, a zone literal) 23; `LocalDate` (date literals, `parseLocalDate`, `LocalDate.ofEpochDay`, `epochDaysToLocalDate`) 24; `Period` 7; `Duration` 5; `LocalTime` (literals, `parseLocalTime`, `LocalTime.of`) 5; `ZonedDateTime` (`parseZonedDateTime`, `Instant#atZone`) 4; others 7. `cargo test -p oxhaven-expr --test formulas`: 0 corpus cases differ; refused 566 at the first commit of the expression work, 553 at the end.

What the formulas do with the new types: the parse and make functions of each (`parseDuration`, `parsePeriod`, `parseTimeZone`, `timeZone`, `parseZonedDateTime`, `parseLocalDate`, `parseLocalTime` and their `Quiet` forms, `epochDaysToLocalDate`, `LocalDate.of`, `LocalDate.ofEpochDay`, `LocalTime.of`, `toLocalDate`, `toLocalTime`, `toZonedDateTime`, `toInstant`, `Instant#atZone`), the date and time literals; `+` and `-` of `(Instant, Duration)`, `(Instant, Period)`, `(LocalDate, Period)`, `(Duration, Duration)`, `(Period, Period)`; `*` of a duration or period by a whole number and `/` of a duration; comparison of dates, times of day and durations, `==` of zones; concatenation; the fields `hourOfDay`, `year`, `dayOfWeekValue` and their relatives of an instant in the zone of each row, of a `ZonedDateTime`, of a `LocalDate` and of a `LocalTime`; `Duration#multipliedBy`, computed and then refused to clients as Java's validator does.

The engine fix: the aggregations read every column type they did not know as a number, and built a result column of nulls for any type but the eight they knew, so `first_by` of a `LocalDate` column (a type that predates this task) gave nulls. They now hold dates, times of day and durations as numbers, a zone as its id, and fail for a type they do not hold (`Period`, `ZonedDateTime`, `LocalDateTime`, `BigDecimal`, `BigInteger`) instead of giving nulls. Ordering a zone (`min`, `max`, `median`, `percentile`) fails, as in Java.

### Refusals left

- `dayOfWeek()` and `LocalDate#getDayOfWeek()` (5 cases): they return `java.time.DayOfWeek`, which is no column type here; it is an `Object` column (below).
- A null literal as a column's value, `(java.lang.Object) B`, `new Object[]{...}`, `true ? null : null` (15 cases): the general `Object` column, below.
- The array comparisons of `java-parser` L1267 to L1287 (6 cases): they return `boolean[]`, below.
- Sorting by, and match filters on, `LocalDate`, `LocalTime`, `Duration`, `ZoneId`, `ZonedDateTime` and `Period` are refused by name (`SortOperation`, `MatchFilter.ColumnTypeConvertorFactory`), as `LocalDate` and `LocalTime` were before; Java sorts all but `ZoneId` and `Period` (probed).
- `Duration`s longer than a `long` of nanoseconds, and dates outside a 32-bit day count (about 5.8 million years either side of 1970), fail here with a message saying so; Java holds them. What Java sends for such a column was not probed.
- The other cases left are no column type: `String.format` (3), `today()` (2), `randomDouble`, `isBusinessDay`, `String.split` (2), casts to `CharSequence` and `Double`, `ColumnType.Normal`, `.class`, `new String(char[], int, int)`, `new Integer[5]`, `new int[4][2]`, a `Vector(Boolean)` column array.

### Design options not taken

**A general `Object` column.** Java sends an `Object` column as Utf8 of `toString` (probed: `(Object) null` is `string`, `deephaven:type` `java.lang.Object`), so the wire is easy; the storage is not. The values a formula makes of type `Object` are of many classes, and what a later formula may do with one (`equals`, `toString`, `instanceof`, a cast back) depends on the class. Options:

1. A `ColumnType::Object` stored as Utf8 of each value's `toString`, with no class kept. Cheap, and right for the corpus's cases (a null column, a cast for display), but a later cast back to the class, or `==` between a `1` and a `"1"`, would be wrong; those would have to be refused, which means the checker must remember that a column is "text of an object" and refuse almost everything on it.
2. A `Struct{class: Dictionary(Utf8), value: Union}` of the known column types, so that each cell keeps its class and its value. Right for every class this server has a type of; every kernel that reads an `Object` would dispatch on the class per cell. This is new storage for the column crate, the engine (sort, aggregation, joins key on it) and the wire.
3. `ColumnType::Object(Box<ColumnType>)`: the static class of the column is one known type, `Object` only in name (`deephaven:type` `java.lang.Object`, cells stored as that type). It covers `(Object) B` and `null` (an all-null column of a chosen type), not a column that mixes classes, which Java allows (`i % 2 == 0 ? (Object) 1 : (Object) "a"`) and which would be refused.

Option 3 is the smallest step that keeps values right; option 2 is where it ends. Either needs `DayOfWeek` (option 3: stored as its name, sent as Utf8 of `toString`, which is what Java sends for an object column) before `dayOfWeek` can be computed.

**`boolean[]`.** `ColumnType::Array(Boolean)` is Java's `Boolean[]` (`list_columns.rs`), which differs from `boolean[]` in its `deephaven:type`, in having nulls, and in being sortable or not. Java sends `boolean[]` as `list<bool>` with `deephaven:type` `boolean[]` and `componentType` `boolean` (probed). Options: a new variant `ColumnType::PrimitiveBooleanArray` (every `list_element()` match then has a new arm, in the engine and server), or a flag on `Array` (`Array { element, primitive: bool }`), which changes every constructor of `Array`. The six corpus cases also need the element-wise comparisons (`eqArray`, `lessArray`), which the checker does not compute yet, so `boolean[]` alone unlocks nothing.

**Object creation as an `Expr` node.** Not needed for the types above: `new String(...)` is handled already, and the six `java.time` classes have no public constructors (their makers are static methods). The constructors left in the corpus (`new Integer[5]`, `new int[4][2]`, `new Object[]{...}`, `new String(char[], int, int)`) are arrays and an `Object` array, which wait on the `Object` column.
