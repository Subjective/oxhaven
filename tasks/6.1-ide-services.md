## Scope

What the web IDE needs from a server to list and open two tables, other than the table
service, Barrage, the websocket transport and the static files:

- Applications with fields (`app::Applications`, `app::Application`): a plain Rust API by
  which the process, and later a script session, offers tables under a name. Field tickets
  `a/<application id>/f/<field name>` and scope tickets `s/<name>` resolve through the ticket
  router, so `FetchTable` and Flight take them.
- `ApplicationService/ListFields`: every field, then the changes, at most one message every
  250 ms, until the client or its session ends.
- The demo application `ide_app` (`app::demo`, `--demo-tables` on the command line) with
  `ide_static` and `ide_ticking` as `oracle/ide/expected.json` defines them.
- `ConsoleService/GetConsoleTypes` answering an empty list; every other console call answers
  `UNIMPLEMENTED` with its name.
- `StorageService/ListItems` over a storage that holds the empty directories `/layouts` and
  `/notebooks`; the calls that read or change files answer `UNIMPLEMENTED` with their name.
- `ApplyPreviewColumns` as a table-service handler.

## Gate

```bash
cargo test -p oxhaven-server --lib -- app:: console:: storage:: ide:: apply_preview_columns
```

The expected answers are Java's, recorded in `crates/oxhaven-server/src/ide/fixtures/java.txt`
and replayed against this server by the tests in `crates/oxhaven-server/src/ide/mod.rs`. To
record them again, start two fresh Java servers (a server that has run the script before holds
the variable it publishes) and run the script with the Python of `oracle/.venv`:

```bash
oracle/ide/bin/start-java-ide.sh 10840 app
oracle/ide/bin/start-java-ide.sh 10841 app --jvm-arg=-Ddeephaven.console.disable=true
oracle/.venv/bin/python crates/oxhaven-server/src/ide/fixtures/capture.py --app 127.0.0.1:10840 --disabled 127.0.0.1:10841 --psk oxhaven > crates/oxhaven-server/src/ide/fixtures/java.txt
oracle/bin/stop-java.sh 10840; oracle/bin/stop-java.sh 10841
```

A server with the two tables, for `pydeephaven` or `oracle/ide/ide-test.js`:

```bash
OXHAVEN_PSK=oxhaven target/debug/oxhaven-server --host 127.0.0.1 --port 10100 --demo-tables
```

## Notes

- `ide_ticking` is the engine's time table (`PT0.5S`) and the engine's `tail(3)`. The
  `update(["N = ii", "Sq = ii * ii"])` between them is a purpose-built column source
  (`app::demo::count_rows`): the formula language has no row variable `ii` yet. It is not a
  general operator: it takes a flat, append-only parent and fails on any other change.
- No engine operator was needed for `ApplyPreviewColumns` (`ops/preview/` does not exist):
  for the ten column types of the contracts the answer is the source table itself, unless the
  request names types and leaves the type of a column out.
- `unported!`, one call:
  `io.deephaven.engine.table.impl.preview.ColumnPreviewManager#makePreviewTable`, reached when
  `unpreviewed_types` is not empty and does not hold the Java name of a column's type. Java
  then shows the column as a `DisplayWrapper`, which the contracts have no column type for.
  The client gets `UNIMPLEMENTED` naming the method.
- Refused with `UNIMPLEMENTED` rather than `unported!`, because a client can send them:
  - every console call but `GetConsoleTypes`;
  - `StorageService` `FetchFile`, `SaveFile`, `MoveItem`, `CreateDirectory`, `DeleteItem`;
  - a `filter_glob` with `[`, `{` or a trailing `\` (`sun.nio.fs.Globs#toUnixRegexPattern`).
- Differences from Java that remain, each listed with its recorded case in `DIFFERENCES` of
  `crates/oxhaven-server/src/ide/mod.rs`:
  - Java with its console disabled does not answer the console calls alike: `GetHeapInfo`
    answers, `ExecuteCommand` and `BindTableToVariable` never answer, some are
    `UNIMPLEMENTED`, the stream variants are `INVALID_ARGUMENT`. Here all are `UNIMPLEMENTED`.
  - A Java server with a console lists a published scope variable in `ListFields` (application
    id `scope`). Here scope variables are never listed, as on Java without a console.
  - The storage is not a directory of the file system: a path that leaves the root and comes
    back by the root's own name is refused here, and nothing can be stored.
  - A field that holds an object that is no table has the type `""`: there are no object type
    plugins.
- Not done: Flight descriptors of fields and scope variables (`app/<id>/field/<name>`,
  `scope/<name>`); the `TicketResolver` trait of the server has no descriptor resolution.
- Not run: `oracle/ide/ide-test.js` against Oxhaven. It needs the websocket transport and the
  static files, which other tasks own.
