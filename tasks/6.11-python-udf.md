## Scope

`t.update("Y = f(X)")` where `f` is a Python function in the scope: the feature that most
distinguishes server-side Python and the hardest part of the console.

This task designs it and builds the first usable form. Recommended shape, to confirm or
replace in `docs/PYTHON_UDF.md`:

- **Resolution**: a call in a formula whose name is no built-in and is a callable Python
  global becomes a `PythonCall` node. Its result type comes from the function's return
  annotation as the reference maps it; without one it is `PyObject` in Java, which the
  contracts cannot hold, so here an annotation is required and its absence is a clear
  error. Record that as an allowed difference only with the owner's agreement.
- **Evaluation is by chunk, not by row**: the evaluator gathers the argument columns of a
  chunk, takes the interpreter lock once, calls the function per row (or once, for a
  function marked vectorized, with numpy arrays over the Arrow buffers), and releases it.
- **Where it may run**: `update` and `select` evaluate when the operation runs and on
  each update cycle; `view`, `update_view` and `where` evaluate on read or on cycle
  threads. Every such thread must take the interpreter lock after the graph lock, never
  the other way round; a console command holds the graph's shared lock and then the
  interpreter lock, and releases the interpreter lock around engine calls. Write the
  order down as a rule and test it with a ticking table whose formula calls Python while
  a command runs.
- **Not in the first form**: `numba` vectorization, Python filters with keyword
  arguments, callables that are not module-level functions, and functions that return
  tables.

Deliver the document, the resolution and chunked evaluation for `update`/`select`/`where`
on static and ticking tables with the annotated scalar types, and the lock test.

it is merged, run the cargo part and report the other as not run.

## Notes

- The recommendation stands on one measurement not yet made: the cost of taking the
  interpreter lock per chunk on cycle threads while a console is busy. Measure before
  building beyond the first form.
- Changes to how the expression engine resolves names may touch
  `crates/oxhaven-contracts` (`FormulaCompiler`): propose the smallest signature.
- If this cannot be made to keep the engine's determinism rule (PORTING.md 7), say so
  and stop: a Python function is allowed to be impure, and Java does not prevent it.
