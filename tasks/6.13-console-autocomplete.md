## Scope

Java completes Python with the library `jedi` running in the script session, fed with the
session's globals. Do the same: documents kept per stream (`open_document`,
`change_document` with incremental edits, `close_document`), then `get_completion_items`,
`get_signature_help`, `get_hover` answered by `jedi` when it is importable, and the
"nothing found" answers of 6.1 when it is not. Diagnostics requests answer as Java does.

Also the browser pair `OpenAutoCompleteStream` and `NextAutoCompleteStream` (gRPC-web
over https cannot stream to the server), with the session-scoped stream bookkeeping the
`BrowserFlight` pair already has.

A completion request must never block a running command for long and must not run under
the graph lock: decide how it shares the interpreter with a long command (Java answers
with the interpreter lock held between byte codes) and write it in the module docs.

## Gate

```bash
cargo test -p oxhaven-server --features python --lib -- console:: && oracle/console/check.sh "$OXHAVEN_ADDRESS"
```

Add completion cases to `oracle/console/probe.py` (items after `emp`, a signature, a
hover, an attribute of a table variable) and record both transcripts with `jedi`
installed on both sides.
