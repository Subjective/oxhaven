## Scope

After 6.1 the buffer holds only what scripts print. Make it the server's log:

- The server's own log records (the `tracing` events) go into the buffer under Java's
  level names, so the IDE's Log panel shows them; decide and document whether the
  duplicate `STDERR` rendering Java sends is reproduced (the IDE shows both).
- A client that does not keep up is ended with `RESOURCE_EXHAUSTED` and Java's text
  rather than buffered without bound; the stream ends when the session does.
- Output written by native code or by subprocesses to file descriptors 1 and 2 (Java
  captures `System.out` and `System.err`, not the descriptors): say what is captured.
- `GetHeapInfo`: choose figures that make the IDE's memory widget meaningful for a
  process without a managed heap (for example allocator statistics for used and
  reserved, and the cgroup or machine limit for the maximum) and document them.

## Notes

- The probe filters Java's own log out of its transcript, so this task is checked by its
  tests and by looking at the IDE's Log panel on both servers.
- Done: the server's `tracing` events are in the buffer under Java's level names, laid out
  as Java's `LOGBUFFER` appender lays them out; a client that falls behind is ended with
  `RESOURCE_EXHAUSTED` and Java's text; the stream ends with the session (`CANCELLED`,
  `Session closed`); `GetHeapInfo` reports the resident set, the allocator's free bytes and
  the control group's limit (`console/memory.rs`). `docs/CONSOLE.md`, "The log stream" and
  "The memory figures".
- The second `STDERR` copy of each log record is not reproduced: it is the oracle's
  logging configuration (`oracle/bin/logback-oracle.xml`), not the Java server's, whose own
  `logback.xml` avoids it.
- Descriptors 1 and 2 are not captured, as in Java (observed with `os.write` and
  `os.system` on 42.9).
- The IDE's Log panel was looked at on both servers after `print(...)` and `1/0` in the
  console: here it lists the start-up warning, the `STDOUT` line and the `ERROR` record
  with the traceback; on the oracle's Java it lists the same and the `STDERR` copies. The
  panel does not show `INFO` on either unless it is switched on.
- Not done: the 100 ms send interval; a flag for the client buffer size.
