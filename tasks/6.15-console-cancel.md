# 6.15 Stopping a running command

- **Status:** open
- **Track:** B
- **Needs:** 6.1 (console design)
- **Owns:** `crates/oxhaven-server/src/console/python/interrupt.rs` (new), `ExecuteCommand` and `CancelCommand` in `crates/oxhaven-server/src/console/mod.rs`

## Read

Paths are in the reference repository at the tag pinned in `oracle/REFERENCE.md`.

- `server/src/main/java/io/deephaven/server/console/ConsoleServiceGrpcImpl.java`
  (`cancelCommand` is not implemented; `executeCommand` runs as an export)
- `server/src/main/java/io/deephaven/server/session/SessionState.java`: what happens to
  running export work when the client cancels the call or the session ends
- `Integrations/src/main/java/io/deephaven/integrations/python/PythonDeephavenSession.java`
  (`doLockedInterruptibly`)
- CPython: `PyErr_SetInterrupt`, `PyThreadState_SetAsyncExc`.

## Scope

A command that never returns holds the graph's shared lock, so no table ticks until the
server is restarted. Find out what Java does when the client cancels the `ExecuteCommand`
call, when the session closes, and when the IDE's cancel button is pressed (observe a
`while True: pass` and a `time.sleep(600)` on the reference), and do the same: most
likely an interrupt delivered to the Python thread as `KeyboardInterrupt`, and the
command answered with that error.

`CancelCommand` stays `UNIMPLEMENTED` if that is what Java answers; the task is the
behavior behind cancelling the call, not that RPC. Engine work in progress when the
interrupt arrives finishes or is abandoned safely: say which.

## Gate

```bash
cargo test -p oxhaven-server --features python --lib -- console::
```

With a test that starts a command that would run for ever, cancels it the way a client
does, and then runs another command and sees a table tick.

## Notes

- A thread blocked in native code cannot be interrupted. Say so in the module docs.
