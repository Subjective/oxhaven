# 6.18 Applications defined by scripts

- **Status:** open
- **Track:** B
- **Needs:** 6.2
- **Owns:** `crates/oxhaven-server/src/app/` (script applications), `crates/oxhaven-server/python/deephaven/appmode.py`

## Read

Paths are in the reference repository at the tag pinned in `oracle/REFERENCE.md`.

- `server/src/main/java/io/deephaven/server/appmode/ApplicationInjector.java`,
  `ApplicationFactory.java`, `ScriptApplicationState.java`
- `application-mode/src/main/java/io/deephaven/appmode/` (`ApplicationConfig`,
  `ScriptApplication`, `ApplicationState`)
- `py/server/deephaven/appmode.py`
- `oracle/ide/app.d/`: an application the reference loads.

## Scope

A directory of `*.app` files (`--app-dir`, Java's `deephaven.application.dir`): each names
an application of type `script` with Python files to run at start. The scripts fill an
`ApplicationState` (`deephaven.appmode`), and its fields are listed and resolved as
application fields (`a/<id>/f/<name>`), which `crate::app` already does for fields set
from Rust. With this the built-in demo application (`--demo-tables`) can become an
`.app` file, and the IDE acceptance test runs against the same application on both
servers.

## Gate

```bash
cargo test -p oxhaven-server --features python --lib -- console:: && cargo test -p oxhaven-server --lib -- app:: ide::
```

and `node oracle/ide/ide-test.js --url "$OXHAVEN_URL"` against a server started with
`--app-dir oracle/ide/app.d`.

## Notes

- Static and `qst` application types have no Python and are not part of this task.
