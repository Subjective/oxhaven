## Scope

The Python API tasks (6.4 to 6.12) need what the operator tasks have: Java's answers,
recorded, and a command that compares. Build it once.

- A **script scenario**: a Python script that runs on the server with `run_script`, and
  the names of the variables to compare afterwards, with optional steps (more script to
  run, or a wait for a ticking table, with the existing "finished" rule). Results are
  read through `s/<name>` tickets and compared under the existing rules of `PARITY.md`.
  A script that must fail is compared by whether it fails and by the Python exception
  type and the `DHError` message prefix, not by the rest of the text.
- `harness record-scripts --url $JAVA_URL` and `harness replay-scripts --url $OXHAVEN_URL
  [--scripts a,b]`, storing recordings like the existing corpus. A script that uses a name
  the server does not have yet is reported as `missing`, not as an error of the run, so a
  baseline can list it.
- Seed scenarios, a handful per later task so each has something to extend: table
  creation, select family, where, sort, head and tail, one of each of agg, update_by,
  joins, dtypes and `new_table`, time, input tables, pandas round trip.
- A client smoke area `console`: `pydeephaven` `run_script`, `open_table`, `bind_table`,
  a script error as `DHError`, and what the session's `tables` lists.
- The gate: build the server with `--features python` in `ci-replay.sh` (the job already
  installs Python 3.13), add the sections `replay-scripts` and `client-smoke console` to
  `oracle/replay-baseline.json` under its existing rules, and say in `oracle/README.md`
  what a machine without Python does (the sections are skipped with a message and exit
  status 2, never silently).
