## Scope

What a user types in the first ten minutes, in this order:

1. Creation: `empty_table`, `time_table` with every `period` and `start_time` form the
   reference accepts (integers, strings, `datetime`/`timedelta`, numpy and pandas types
   when importable), `merge`, `merge_sorted`.
2. Properties and inspection: `size`, `is_refreshing`, `is_blink`, `is_flat`, `columns`,
   `column_names`, `definition`, `meta_table`, `has_columns`, `to_string`, `attributes`,
   `__repr__`, iteration (`iter_dict`, `iter_tuple`, `iter_chunk_dict`, `iter_chunk_tuple`).
3. Selection: `update`, `lazy_update`, `view`, `update_view`, `select`, `drop_columns`,
   `move_columns` (and `_up`, `_down`), `rename_columns`, `select_distinct`.
4. Filtering: `where`, `where_in`, `where_not_in`, `where_one_of`, `head`, `tail`,
   `head_pct`, `tail_pct`, `slice`, `slice_pct`.
5. Ordering: `sort`, `sort_descending`, `reverse`, `restrict_sort_to`.
6. Shape: `flatten`, `snapshot`, `snapshot_when`, `ungroup`, `coalesce`.

Rules of `docs/CONSOLE.md` apply. Where the table service has an operation, the method
builds its request. Where it has none (`reverse`, `rename_columns`, `move_columns`, the
`_pct` forms, `where_one_of`, `restrict_sort_to`, attributes), do not emulate it with
other operations unless Java itself defines it that way: add a local operation in
`console/python/ops.rs`, one registered function per operation that takes typed arguments
as JSON and calls the engine's Rust API under the same lock and `unported!` handling as
`table::run_local`. If the engine operator does not exist, the method raises with the Java
method's name and the operator is listed in Notes for an engine task.

Filters given as `deephaven.filters.Filter` objects, `Selectable` objects, and Python
callables are not part of this task: strings and sequences of strings only.

cargo test -p oxhaven-server --features python --lib -- console:: && oracle/bin/harness replay-scripts --url "$OXHAVEN_URL" --scripts table_

## Notes

- Sized for one agent context. If the list does not fit, finish the part that users type
  first, list the rest here, and stop.
- A method whose engine operation is missing raises `DHError` naming the Java method, from
  the handler's `UNIMPLEMENTED`; it is never left out silently and never approximated.

### Outcome

Blocked on the replay part of the gate, not on the Python: `replay-scripts --scripts table_`
has `table_error`, `table_first_steps` and `table_sort` clean and four scenarios that differ
only where an engine operator is missing. Their methods raise `DHError` from `UNIMPLEMENTED`,
as the note above asks, which the baseline lists as `script_failure_unexpected` and
`failure_unexpected:NOT_FOUND`, not as `missing`; that change of kind is a protected one
(`oracle/README.md`, "The replay gate"), so the four lines are left as they were and the gate
reports `NEW KIND` for them until the operators exist or the lines are changed under the
`oracle-change` label.

Engine operators that do not exist, each refused by name in `console/python/ops.rs`
(`OPERATIONS`) and waiting for an engine task:

| Python | Java | Scenario step that waits |
| --- | --- | --- |
| `head_pct`, `tail_pct`, `slice_pct` | `QueryTable#headPct`, `#tailPct`, `#slicePct` (`SliceLikeOperation`) | `table_head_tail` 1 to 3 |
| `rename_columns`, `move_columns`, `move_columns_up`, `move_columns_down` | `QueryTable#renameColumns`, `#moveColumns` (`renameColumnsImpl`); with no column Java returns the table, and so does this | `table_select` 1 to 4 |
| `restrict_sort_to` | `QueryTable#restrictSortTo`, and `sort` honouring it | `table_select` 5 |
| `where_one_of` of several filters | `QueryTable#where` of a `FilterOr` of filter strings: the engine has the disjunction (`FilterSpec::Or`) but no public function that takes strings; one filter is `where` | `table_where` 1 |
| `merge_sorted` of static tables | `TableTools#mergeSorted`, refused by the `merge` handler; of refreshing tables Java fails, and so does this | `table_creation` 2 |
| `attributes` | `AttributeMap#getAttributes`: a table keeps `TableAttributes` and its sort marks, not Java's map (`SortedColumns`, `SortRowRedirection`, `AddOnly`, ...) | none |

Not written, for other tasks:

- `iter_dict` and `iter_tuple` of an `Instant` column, or of an array or vector column, raise
  `DHError`: Java hands out `java.time.Instant` and array objects (6.8, 6.9). The chunk
  iterators give an `Instant` column as `datetime64[ns]`, as Java does.
- `to_string` of an `Instant` column (`DateTimeUtils#formatDateTime` in the server's time
  zone) and of an array column raise `DHError`.
- `Table.columns` holds a stand-in for `deephaven.column.ColumnDefinition` whose `data_type`
  is the Java type name, and `TableDefinition` is built from a table only (6.8).
- `where_in` and `where_not_in` with no column: Java answers (every row, or none), the
  `where_in` handler refuses the request.
- Not in the scope list and not written: `is_failed`, `update_graph`, `with_attributes`,
  `without_attributes`, `remove_blink`, `with_order_for_column`, `assert_sorted`.

Outside the owned paths, each change small: `deephaven/__init__.py` exports `merge`,
`merge_sorted` and `SortDirection`; `console/python/mod.rs` declares and registers `ops`;
`console/python/tests.rs` opens its `Python` fixture to the tests of `ops.rs`.
