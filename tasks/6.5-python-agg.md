## Scope

`from deephaven import agg` with every function of the reference module, each returning
an object that renders itself as the `Aggregation` message of the table service, and the
table methods above. `agg_by` with `preserve_empty` and `initial_groups`.
`agg.formula`, `agg.partition` and whatever else the handlers answer `UNIMPLEMENTED` to
raise with that text.

Not `partitioned_agg_by` (7.6).

## Notes

- Sized for one agent context. If the list does not fit, finish the part that users type

### Outcome

`deephaven.agg` has every function of the reference module, and `Table` has `agg_by`,
`agg_all_by` and the dedicated aggregations (`group_by`, `first_by`, `last_by`, `sum_by`,
`abs_sum_by`, `weighted_sum_by`, `avg_by`, `weighted_avg_by`, `std_by`, `var_by`, `median_by`,
`min_by`, `max_by`, `count_by`, `head_by`, `tail_by`). `replay-scripts --scripts agg_` has
`agg_dedicated` clean and `agg_by` differing in two late steps, listed in
`oracle/replay-baseline.json` with `script_failure_unexpected` and
`failure_unexpected:NOT_FOUND`, a change made under the `oracle-change` label.

Refused by the aggregation handler because the engine has no operator, each raising `DHError`
with the Java name:

| Python | Java | Scenario step that waits |
| --- | --- | --- |
| `agg.partition` | `AggregationAdapter#adapt` of the partition aggregation | `agg_by` 6 |
| `agg_by(..., initial_groups=...)` | `QueryTable#aggBy` with initial groups | `agg_by` 7 |
| `agg.count_where(col, [])` | `CountWhereOperator#applyFilters` with no filter | none |

Not written:

- `partitioned_agg_by` (7.6).
- Filters are strings; a `Filter` object is not accepted by `count_where`.
- `agg.formula(..., reaggregating=True)` builds, and `agg_by` refuses it with Java's text for
  a table that is not a rollup.
- `agg_by([])` fails as in Java, with the handler's cause text in place of Java's.

Outside the owned paths, shared with 6.6 and 6.7: `console/python/checks.rs` (new) gives the
package Java's check of a column name and of a duration and the handler's check of one
update_by operation, and holds the tests; `console/python/mod.rs` registers it;
`table/ops/mod.rs` and `table/ops/update_by.rs` open those two checks to it.
