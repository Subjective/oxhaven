# 6.6 Python API: update_by

- **Status:** open
- **Track:** P
- **Needs:** 6.4
- **Owns:** `crates/oxhaven-server/python/deephaven/updateby.py`, `Table.update_by` in `crates/oxhaven-server/python/deephaven/table.py`, script scenarios `updateby_*`

## Read

- `docs/CONSOLE.md`: the design, and the rule that a table operation goes through the table
  service handler (`deephaven/_engine.py`, `table_op`).
- `crates/oxhaven-server/python/deephaven/table.py` and `table_factory.py`: how the existing methods are written.

Paths are in the reference repository at the tag pinned in `oracle/REFERENCE.md`. Read the reference package for names, signatures, argument conversion and error
message texts. Do not copy its code or docstrings: it is not open source (`docs/CONSOLE.md`).

    - `py/server/deephaven/updateby.py`: `OperationControl`, `DeltaControl`, `BadDataBehavior`,
      `MathContext`, and every operation function (cumulative, exponential moving by tick
      and by time, rolling by tick and by time, delta, forward fill).
    - `crates/oxhaven-server/src/table/ops/update_by.rs` and the `UpdateByRequest` message.

## Scope

`from deephaven import updateby` (commonly `import deephaven.updateby as uby`) with every
function of the reference module rendering the `UpdateByRequest` operation it stands for,
and `Table.update_by(ops, by)`. Time arguments in every form the reference accepts
(integers in nanoseconds, duration strings). Operators the engine has not ported raise
with the handler's text.
