## Scope

`from deephaven import updateby` (commonly `import deephaven.updateby as uby`) with every
function of the reference module rendering the `UpdateByRequest` operation it stands for,
and `Table.update_by(ops, by)`. Time arguments in every form the reference accepts
(integers in nanoseconds, duration strings). Operators the engine has not ported raise
with the handler's text.

### Outcome

`deephaven.updateby` has every function of the reference module with `OperationControl`,
`DeltaControl`, `BadDataBehavior` and `MathContext`, and `Table.update_by(ops, by)`. An
operation is checked when it is made, as in Java, by the handler's own check of the message
(`check_update_by_operation` in `console/python/checks.rs`). `replay-scripts --scripts
updateby_` is clean for `updateby_cumulative`, `updateby_rolling`, `updateby_exponential` and
`updateby_time`; the count where and the rolling formula run since the engine has them.

Nothing is refused for a missing operator. Differences from Java that no scenario holds:

- `rolling_sum_tick("S = V", rev_ticks="3")`: Java accepts the string through an overload of
  its bridge; here it is a `DHError`, as for any other value that is not an integer.
- `update_by([])` fails on both, with the handler's cause text in place of Java's.
