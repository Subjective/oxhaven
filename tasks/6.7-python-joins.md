## Scope

The join methods with the reference's argument forms (`on` and `joins` as a string or a
sequence, `type`/`NaturalJoinType`, `aj`/`raj` match expressions, `range_join` with its
aggregations from 6.5), `multi_join` in both of its call forms. `keyed_transpose` if its
engine operation exists; otherwise it raises and is listed.

### Outcome

`Table` has `natural_join` (with `NaturalJoinType`), `exact_join`, `join`, `aj`, `raj` and
`range_join`; the module has `MultiJoinInput`, `MultiJoinTable`, `multi_join` in both call
forms and `keyed_transpose` with `NewColumnBehaviorType`. `replay-scripts --scripts join_` has
`join_natural`, `join_cross_and_asof` and `join_range` clean and `join_multi` differing in its
last step, listed in `oracle/replay-baseline.json` with `script_failure_unexpected` and
`failure_unexpected:NOT_FOUND`, a change made under the `oracle-change` label.

Refused because the engine has no operator:

| Python | Java | Scenario step that waits |
| --- | --- | --- |
| `keyed_transpose` | `KeyedTranspose#keyedTranspose`, refused by name in `console/python/ops.rs` (`OPERATIONS`) | `join_multi` 6 |

Differences from Java that no scenario holds, each a refusal of the handler where Java answers:

- `range_join` with no aggregation: Java returns the left table's columns; the handler
  requires one aggregation.
- `multi_join` with no key column (`on=""`, `on=[]`, `MultiJoinInput(t, [])`): Java joins on
  no key or fails in its own way; the handler refuses the request.
