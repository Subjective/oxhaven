## Scope

A Python plugin package that registers a JS plugin has its files served under
`/js-plugins/<name>/` and listed in `/js-plugins/manifest.json`, as Java's Python server
does. A request must not leave the plugin's directory; where Java lets one, nothing outside
is served and the difference goes to the owner.

Then what `deephaven-plugin-plotly-express` needs of the `deephaven` package where that is a
real and bounded piece of it: `deephaven.server.executors`, `LivenessScope.manage` of a
partitioned table, `deephaven.calendar`. No `jpy` module: report what the plugin calls.

Then the figure check in the web IDE again, for a `by` figure, on both servers.

`deephaven.ui` is out of scope but for the list of what its import needs.

## Notes

- The design and the observations of Java are `docs/JS_PLUGINS.md`; executors, calendars and
  the liveness of a partitioned table are in `docs/CONSOLE.md` ("Listeners, locks, liveness
  scopes and execution contexts"); the repeated trial of the two plugins is in
  `docs/FIGURES.md` ("After task 7.10.1").
- Java was probed with a package that registers 86 plugins of different shapes (names,
  mains, loaders, links) and three rounds of HTTP requests against both servers; the first
  line of every registration's outcome is the same on both, and the answers differ only in
  what `docs/JS_PLUGINS.md` lists.
- Java serves a link to a file outside the plugin's directory. Here it is not served. For
  the owner's ruling (`docs/JS_PLUGINS.md`, "For the owner"); `PARITY.md` has no entry.
- The server does not start with `deephaven-plugin-plotly-express` installed: the plugin
  imports `jpy`. With a stand-in module in a scratch environment the plugin's JS is loaded
  by the web client and 42 of 50 figures are sent as Java sends them.
- Refused, with the Java method of each: the six functions of `deephaven.calendar`
  (`io.deephaven.time.calendar.Calendars`), a new named executor
  (`PythonDeephavenSession#registerJavaExecutor`), a `loader` that is no JSON
  (`JsPluginManifestEntry#loader`).
- The `by` figure of `deephaven.plot` in the web IDE was the same on both servers as main
  stood: nothing to fix.
