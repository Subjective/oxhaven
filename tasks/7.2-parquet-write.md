## Scope

The design is `docs/STORAGE.md`, "Writing Parquet": what a file holds, what is refused and
which Java method each refusal names, and the differences from Java.

`write`, `batch_write` and `delete` of `deephaven.parquet`, with `RowGroupInfo`, column
instructions, a table definition, the codec names and the dictionary limits: files that
the Java server reads back as the table it reads from its own file of the same table.

Not in this task, each refused by name: partitioned writes, `_metadata` files, data index
files, object codecs, `LZO`, destinations with a URI scheme.

## Gate

```bash
cargo test -p oxhaven-parquet write
cargo test -p oxhaven-server --features python --lib parquet
oracle/bin/harness replay-scripts --url $URL --scripts parquet_write_
```

## Notes

- Partitioned writes and metadata files need partitioning columns in the contracts, as
  the partitioned reads of 7.1 do. Index files need data indexes.
- The files of the two servers were compared by reading both sets in the Java
  reference; the replay gate compares what each server reads from its own files, and
  their footers.
