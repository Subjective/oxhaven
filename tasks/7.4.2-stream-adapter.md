## Notes

- **One adapter.** `stream_table` replaces the two copies of the blink refresh (the blink
  input table's and the Kafka crate's). Its order is Java's: failures handed over are
  delivered first, then the flush callback runs, then failures the callback handed over,
  then the rows; several failures of one cycle are one failure whose text lists them
  (`MultiException`). A failure ends the stream (`StreamToBlinkTableAdapter#close`): the
  publisher is no longer alive, later `add` and `fail` do nothing, the shutdown callback
  runs once. The stream also ends when the table is dropped: the table owns its update
  source, whose `Drop` is Java's `destroy`.
- **`blink_to_append_only` is memoized** as Java's is (`QueryTable.memoizeResults` is on
  by default): asked again of the same blink table with the same limit while the first
  result is alive, it returns that result, with the rows it collected since. Probed:
  `blink_to_append_only(t)` twice, and `t.head(2)` twice, are the same table in Java. The
  results are remembered weakly in a process-wide list, as `copied.rs` remembers copies by
  address, because the `Table` contract has no place for them.
- **Kafka** makes a stream table per `consume`; its shutdown callback stops the polling
  thread. `TableType.append()` is now `blink_to_append_only` of the blink table, a second
  node as in Java, instead of a root table that appended itself.
- **Python.** `deephaven.stream.table_publisher` (`table_publisher`, `TablePublisher`)
  and `deephaven.stream.blink_to_append_only` and its deprecated synonym
  `stream_to_append_only`. `update_graph` is accepted and has no effect: the server has
  one graph. `chunk_size` is only checked (`chunkSize must be positive`). `add_only_to_blink`
  is still refused, now inside the `DHError` the reference raises.
- **Probed on Java 42.9** (port 10986, scripts not in the repository): the attributes of
  the table; `add` of a table with extra columns, a missing column
  (`NoSuchColumnException`), a column of another type (`ClassCastException`), a value
  that is not a table (`AttributeError`); `chunk_size=0`; `blink_to_append_only` of an
  append-only and of a static table (`Input is not a blink table!` in a `DHError`); two
  failures in one cycle; `add` and `publish_failure` after the failure; a flush callback
  that adds rows and one that raises; a liveness scope that releases the table (the
  shutdown callback runs before the `with` block ends); `del` of a table made outside a
  scope (Java: the session keeps it, no shutdown).
