## Scope

librdkafka (the `rdkafka` crate) as the `RecordSource` of `consume`, in place of the wire
client of the first slice. What that client refused and librdkafka gives: `offsets` left
at its default (committed offsets and `auto.offset.reset`), compressed batches, a broker

## Notes

- **Licences.** Only what the ruling covers is built: librdkafka's own sources with its
  bundled snappy and lz4, and Zstandard from `zstd-sys`. Off, and why: gzip (needs an
  external zlib, or the one bundled in `libz-sys`, which the ruling's wording does not
  reach), TLS (OpenSSL), SASL other than PLAIN (OpenSSL, Cyrus SASL), OIDC (libcurl).
  `docs/KAFKA.md`, "The client library", has every crate and file with its licence.
- **The wire client is removed**, with `kafka-protocol`, `crc`, `crc-catalog` and
  `crc32c`, and with its three unit tests of record batch decoding, which tested code
  that no longer exists. `docs/KAFKA.md`, "The wire client is removed".
- No `unsafe`: the `rdkafka` crate's safe interface is enough.
- No `unported!` call and no change to `crates/oxhaven-contracts`, `oracle/` or
  `PARITY.md`. Refusals name the Java method (`docs/KAFKA.md`, "Refused, by Java
  method"): gzip, `security.protocol`, `auto.offset.reset=by_duration:...`.
- **Changed from the first slice:** a property value that is not a `str` is now an error,
  as in the reference; an unreachable broker fails the call after
  `default.api.timeout.ms` (60 seconds) and no longer at once, as in the reference; a
  broker that goes away no longer fails the table.
- Compared with Java 42.9 by hand: both servers on one broker (`apache/kafka:3.9.1` in
  Docker), 33 tables, 25 calls, the offsets of eight consumer groups, a restart of the
  broker. `docs/KAFKA.md`, "Differences from Java seen in the probes". The probe scripts
  are not in the repository.
- For the owner (`docs/KAFKA.md`, "For the owner's ruling"): gzip; TLS and SASL; the
  order of `kafka.topics`; property values that are not text; values outside
  librdkafka's ranges. The three questions of the first slice stay open.
- Outside the owned paths: `console/python/kafka.rs` and its line in
  `console/python/mod.rs` (the native function for `topics`), and the `kafka-broker` job
  in `.github/workflows/ci.yml`, which the task allowed. The job has not run on GitHub.
- Not verified: see the end of "Tests and the broker" in `docs/KAFKA.md`.
