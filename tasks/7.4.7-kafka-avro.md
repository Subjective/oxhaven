## Scope

The 7.4.7 row of `docs/KAFKA.md`, "Tasks": `consumer.avro_spec` for the key and the
value, with the schema given as JSON text or by subject and version from a
Confluent-compatible schema registry (`schema.registry.url`, plain `http://`); Java's
columns for each Avro type (nested records flattened with Java's separator, unions with
null, the logical types Java maps), `mapping` and `mapped_only`; the Confluent wire format
(magic byte, schema id) and records whose writer schema differs from the spec's; Java's
failures for bad schemas, unknown subjects and records that cannot be decoded. Each
behaviour is probed on the Java reference with the same broker and registry, and covered
by unit tests and by an Avro round trip in the `kafka-broker` job.

Out of scope: Protobuf (7.4.8), Avro when producing (7.5.2), `cdc` (7.5.3), TLS and SASL,
an `https://` registry.

## Notes

**No new crate.** The licence check of step 0 passed for `apache-avro` 0.22.0 (every
crate it adds is Apache-2.0 or MIT), but the crate was not kept: its schema resolution
works on decoded values and is more lenient than Java's (a writer's long is read as a
reader's int, a double as a float, a map as a record), its texts are not Avro Java's,
and the failures of a record are part of what this task reproduces. Avro is read by
`src/avro.rs` (the parser with Avro 1.12's checks and texts, the binary decoder, and
`ResolvingDecoder`'s resolution), the columns and cells are made by `src/avro_spec.rs`,
and `src/registry.rs` is the registry client: HTTP/1.1 over `std::net::TcpStream`, no
HTTP client crate, no TLS. `Cargo.lock` is unchanged.

**The registry in tests.** No registry image: `tests/avro.rs` and the round trip in
`tests/broker.rs` each serve a stub registry on `127.0.0.1` from the test, answering the
paths Java's client asks for. The `kafka-broker` job needs nothing more than before.

**Probes.** Java on port 10968, Oxhaven on 10969, one broker (`apache/kafka:3.9.1`) and a
stub registry (Confluent's REST paths and error bodies; it logged every request, which is
where the paths and query strings above come from). Six rounds, 145 cases: 54 on types,
mappings, the registry and the wire format; 42 on schema errors, decimals, nesting, enums,
promotions, invalid UTF-8 and writer schemas that are not records; 18 on promotions,
arrays, decimal nulls, magic bytes and mappings to `None`; 25 on arrays of unions and on
invalid UTF-8; 3 on `type` nodes; 3 on registry URLs without `http://`. Each case compares the call's error, or the schema
(with `deephaven:type`), the rows and whether the table failed.

- Same in 130: every schema, row and failure of a table, and every error of a call,
  among them the parser's texts, the registry's errors (`Version 3 not found.; error
  code: 40402`, `Subject ... not found`, `NumberFormatException` for a version that is
  not a number), a missing `schema.registry.url`, the wire format's errors, and the
  quirks Java has (null sentinels, wrapping timestamps, the decimal batch that stays null
  after its first null, `Zero length BigInteger`, enum arrays that fail when not empty,
  Instant arrays of a union refused at `consume`).
- Refused by name in 14, where Java makes a column its clients cannot read
  (`bytes` and `fixed` as ByteVector filled with ByteBuffer or GenericFixed, Boolean[]
  filled with Object[]) or holds Java objects (unions of more than null and one type,
  maps, the null type, arrays of records), or fails at the first value (a decimal in a
  fixed), an `https://` registry (Java: `SSLException` against the stub) and an
  `ftp://` one (Java: a ClassCastException).
- Different in text only in 1 (`PARITY.md` A5): a schema that is not JSON. Java gives
  Jackson's text, here the JSON parser's, both inside `SchemaParseException`.

Not probed: a real Confluent registry (the stub answers as Confluent's documentation and
Java's client expect; Java's deserializer also asks `/associations/...` first and goes on
after its 404, which Oxhaven does not ask); schema references; registries that need
authentication; a key spec read from a subject (only a key with a text schema).
