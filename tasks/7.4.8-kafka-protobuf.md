## Scope

The 7.4.8 row of `docs/KAFKA.md`, "Tasks": `consumer.protobuf_spec` for the key and the
value, with the descriptor from a Confluent schema registry (`schema`, `schema_version`,
`schema_message_name`) or from a message class (`message_class`), `include` paths, and
`protocol` (`ProtobufProtocol.serdes()` with Confluent's message indexes, and `raw()`);
Java's columns for each field of the descriptor (scalars, nested messages flattened with
Java's names, repeated fields, maps, oneofs, enums, optional presence, the well-known
types), each ported where the engine has its column type and refused by name otherwise;
Java's texts for unknown subjects, missing message names and records that cannot be
decoded. Each behaviour is probed on the Java reference and this server with the same
broker and a request-logging registry stub, and covered by unit tests and by a Protobuf
round trip in the `kafka-broker` job.

Out of scope: Protobuf when producing (Java has none), `cdc` (7.5.3), TLS and SASL.
