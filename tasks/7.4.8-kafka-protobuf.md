## Scope

The 7.4.8 row of `docs/KAFKA.md`, "Tasks": `consumer.protobuf_spec` for the key and the
value, with the descriptor from a Confluent schema registry (`schema`, `schema_version`,
`schema_message_name`) or from a message class (`message_class`), `include` paths, and
`protocol` (`ProtobufProtocol.serdes()` with Confluent's message indexes, and `raw()`);
Java's columns for each field of the descriptor (scalars, nested messages flattened with
Java's names, repeated fields, maps, oneofs, enums, optional presence, the well-known
types), each ported where the engine has its column type and refused by name otherwise;
Java's texts for unknown subjects, missing message names and records that cannot be
decoded. Each behaviour is probed on the Java reference and this server with the same
broker and a request-logging registry stub, and covered by unit tests and by a Protobuf
round trip in the `kafka-broker` job.

Out of scope: Protobuf when producing (Java has none), `cdc` (7.5.3), TLS and SASL.

## Notes

**What is built.** `protobuf_spec(schema=..., schema_version=..., schema_message_name=...,
include=..., protocol=...)` for keys and values, as `docs/KAFKA.md`, "How a Protobuf field
becomes a column", describes. `message_class` is refused by name
(`io.deephaven.kafka.protobuf.DescriptorMessageClass#of`): it names a Java class on the
reference's classpath, which this server has no counterpart of. New code:
`crates/oxhaven-kafka/src/protobuf.rs` (compiling the registry's `.proto` text with
`protox`, finding the message, reading the binary encoding as protobuf-java's
`DynamicMessage` does, the serdes framing) and `protobuf_spec.rs` (Java's parser:
descriptor to columns, and the cells). `registry.rs` gains the Protobuf fetch with its
references. No new crate: `prost-reflect` 0.16.5 and `protox` 0.10.0 (both MIT OR
Apache-2.0, with `protox-parse`, `logos` and `miette`, Apache-2.0 or MIT) were already in
`Cargo.lock` as build dependencies of `oxhaven-proto`; `Cargo.lock` only lists them under
`oxhaven-kafka` now.

**Probes.** Java on 10918, Oxhaven on 10919, one broker (`apache/kafka:3.9.1`) and a stub
registry that serves `schemaType` and references and logs every request. Two rounds, 140
cases: 90 on types, nesting, presence, oneofs, repeated fields, maps, enums, well-known
types, `include`, the wire format and its failures, the spec's checks and `message_class`;
50 on message names, references, recursion limits, NullPointerException texts, maps of
messages, proto2 required fields, versions and keys. Each compares the call's error, or
the schema (with `deephaven:type`), the rows and whether the table failed; the texts of
failed tables were read from Java's log and are asserted in the tests.

- Same in 117, every registry request among them, in the same order (a key and a value of
  one subject fetch it once, as Confluent's cached client does).
- Refused by name in 20: 16 where Java makes a column of Java objects (enums as
  `EnumValueDescriptor`, maps of one value column as `java.util.Map`, repeated messages
  whose field has presence as `Integer[]`, `int[][]`, `Any`, `FieldMask`), 4 with
  `message_class`.
- Different in text only (`PARITY.md` A5) in 3: a `.proto` Java's parser refuses (the
  words after `Could not parse Protobuf - ` are `protox`'s, not Wire's), and
  `DHError("text")`, whose `str()` the reference writes as `text : text` and this
  package's `dherror.py` as `text` (not a file this task owns).

Not probed: a real Confluent registry; schema references nested more than one deep (here
followed recursively, refused past 32); a `.proto` with imports neither referenced nor
well-known.

**Tests.** Unit tests in `protobuf.rs` (wire failures and their texts, the recursion
limit, unknown fields and merging, required fields, the serdes framing, message names);
`tests/protobuf.rs` (columns and cells of every kind, `include`, schema and message
failures, record failures, the registry's requests and its cache); the console's
`protobuf_spec` checks; a round trip in `tests/broker.rs` (registry stub in the test,
serdes with message indexes, a reference). Each was broken once to see it fail.
