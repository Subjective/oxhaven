## Scope

The 7.5.1 row of `docs/KAFKA.md`, "Tasks": `deephaven.stream.kafka.producer.produce` over
librdkafka's producer, with `simple_spec`, `json_spec` and `KeyValueSpec.IGNORE`,
`publish_initial`, `last_by_key_columns`, the default `partition`, and the records Java
publishes for the rows a table has and for the adds, removes and modifies of each cycle.
The returned callback stops publishing. Avro and raw specs and the topic, partition and
timestamp columns are 7.5.2 and are refused by name.

Each behaviour is probed on the Java reference with a real broker before it is decided:
the records of the initial rows and of each kind of change, with and without
`last_by_key_columns`, keys and values byte for byte, nulls, the partition and timestamp
of records, the callback, a table that fails, a broker that cannot be reached. Broker
tests in `crates/oxhaven-kafka/tests` cover producing, with a produce-then-consume round
trip, so that the `kafka-broker` job runs them.

Refusals and differences decided after probing Java:

- `ModifiedColumnSet` ALL is refused by naming `ModifiedColumnSet#containsAny`. Java throws
  an NPE in `PublishListener` and stops publishing.
- `transactional.id` is refused; Java fails only after 120 s.
- `compression.type=gzip` is refused, because it needs libz.
- A `nested_delim` that is a regular expression is refused by naming `String#split`.
- An encoding outside these six names is refused by naming `Charset#forName`: UTF-8,
  UTF-16, UTF-16BE, UTF-16LE, ISO-8859-1, US-ASCII.
- In JSON, columns of Duration, Period, LocalDateTime, ZonedDateTime, vector and array
  types are refused. Java prints `toString`, which is an identity hash for arrays.
- An unreachable broker: the publication waits for `max.block.ms` once, where Java waits
  once per record.
- A record with no key goes to librdkafka's random partition, where Java uses its sticky
  partitioner.
- The JSON `exclude_columns` bug is reproduced as Java's "no matching Java method
  overloads found".
- `topic_col`, `partition_col` and `timestamp_col` are refused for 7.5.2.
