# 7.7b Make the block row set the engine's row set

- **Status:** in review
- **Track:** C
- **Needs:** 7.7
- **Owns:** `crates/oxhaven-contracts/src/rowset/`, `crates/oxhaven-rowset/`,
  `crates/oxhaven-testkit/src/range_rowset.rs`, `docs/ROWSET.md`, and the callers of
  `RowSet::ranges` in every crate

This is a change to `crates/oxhaven-contracts`, approved by the owner on 2026-11-17. The pull
request carries the `oracle-change` label. It changes nothing under `oracle/` and not
`PARITY.md`.

## Scope

`docs/ROWSET.md`, "Making it the engine's row set", is the specification and now records what
was done.

1. Move `crates/oxhaven-rowset/src/blocks` into `oxhaven-contracts` as the body of
   `rowset::RowSet`, with the name and every method kept and the same results.
2. `RowSet::ranges` becomes an iterator of `RowRange`; callers that used the slice are
   rewritten, with a method of `RowSet` where they need more than a walk.
3. The row-set tests ported from Java run against the new type, at Java's sizes where the
   quick test run stays reasonable.
4. The vector of ranges stays available to tests as a reference.

No behavior changes. A test whose result changes shows a defect in the swap.

## Notes

Where things are:

- `crates/oxhaven-contracts/src/rowset/`: `mod.rs` (the row set), `container.rs` (one block),
  `merge.rs` (set algebra), `tests.rs` (a sorted-set model and the layout).
- `oxhaven_testkit::RangeRowSet`: the vector of ranges, for tests and the benchmark only.
- `crates/oxhaven-rowset/tests/blocks.rs`: every operation compared with `RangeRowSet`.
- `crates/oxhaven-rowset/examples/rowset-bench.rs`: the micro-benchmark. It was a binary of
  the crate; it is an example now because it needs the testkit, which is a development
  dependency.
- `crates/oxhaven-engine/examples/fragmented-rows.rs`: the end-to-end timing in `docs/ROWSET.md`.

Added to `RowSet`, each because a caller used the slice for it:

- `range_count()`: the number of ranges, from the spans.
- `as_single_range()`: the range of a contiguous row set, in constant time.
- `overlaps_range(first, last)`: Java's `RowSet#overlapsRange`, which was `shift::has_key_in`.
- `check_layout()` and `SpanCounts`, hidden from the documentation: the layout check that the
  comparison test needs from outside the crate.

`oxhaven_rowset::BlockRowSet` and the `blocks` module are gone; the type is `RowSet`.

Callers that changed shape:

- `ops/agg/aggregator.rs` `chunks` and `server/table/ops/column_statistics.rs` `chunks_of`:
  were a walk over the slice with an index and an offset; each chunk is now
  `sub_set_by_position_range`.
- `ops/merge/flatten.rs`: `keys_at_positions` built a prefix sum over all ranges on every call
  and searched it; it calls `RowSet::get`. `position_shifts` walks two range iterators and
  keeps what is left of the current range of each. `pivoted` (`reverse`) maps the ranges
  without `rev` and lets `from_ranges` sort them.
- `ops/select/arrays.rs`: `windows(2)` over the ranges became a walk that remembers the end
  of the previous range.
- `ops/ungroup/keys.rs` `sizes_in`: an index into the slice became a peekable iterator.
- `oxhaven-column/src/flat.rs` and `server/hierarchical/subscription.rs`: a slice pattern and
  `ranges().len() > 1` became `as_single_range()`.
- `oxhaven-rowset` `RowSetBuilderRandom::add_row_set`: a row set of more than 64 ranges is
  added by union, not copied range by range. `union_all` goes through it.
- The other callers dropped `.iter()` or `.copied()` and are otherwise as they were.

Ranges are still collected into a vector in two places, both to build a new row set:
`pivoted` in `ops/merge/flatten.rs` (the mirrored ranges come out in decreasing order) and
the two builders of `oxhaven-rowset`, which hold ranges until `build`.

Tests: no expectation changed. `crates/oxhaven-rowset/tests/rowset.rs` compares `ranges()`
through a helper that collects them. Five ported tests went back to Java's sizes
(`testMinusRandom`, `testMinusRandomRanges`, `testMinusIndexOps`, `testRandomInsertMinus`,
`MixedBuilderTest#testMixedBuilder`); the third and fourth run the first fifth of their rounds
under the quick seed budget, because they take 37 and 22 seconds unoptimized in full.

No `unported!` calls were added.
