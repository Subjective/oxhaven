## Scope

The design is `docs/HIERARCHICAL.md`. This task wrote it and built its first slice; the rest
is the tasks below, which the plan takes up as files of their own. The whole of rollup was
too much for one task: the first slice alone is the engine's walk, a service, an object
type, a second kind of Barrage subscription, the browser's upload and a harness directive.

Done here:

- `rollup` of static and ticking tables by any number of columns, with every aggregation
  Java allows in a rollup but `CountWhere`, `Group` and `AggFormula`; Java's refusals of
  the others, in Java's words.
- Views: a rollup with a key table that expands, expands with all descendants, contracts
  or expands to a depth, static or ticking; the snapshot of a range of rows of a view,
  which visits expanded nodes only and reads the rows of the range only.
- `HierarchicalTableService`: `Rollup`, `View` (of a rollup or of another view's rollup),
  `ExportSource`; the checks of `Apply`. The object type `HierarchicalTable` in
  `ListFields`, `FetchObject` and `MessageStream`, with Java's snapshot schema.
- The Barrage subscription to a view over `DoExchange`: a snapshot of the viewport when
  the viewport, the columns, the source or the key table change.
- `BrowserFlightService/OpenDoPut` and `NextDoPut`, with which the web client uploads the
  key table.
- Python: `Table.rollup` and `RollupTable` with `aggs`, `by` and `include_constituents`.
- The harness directive `# oracle: views`, which compares views of a rollup between the
  servers, and the IDE route `rollup`.

- Not checked: a sort or a filter of a rollup with constituents (7.8.3), and the IDE's

## Notes

- No contract changed.
- **Needs a ruling:** `SortedFirst` and `SortedLast` in a rollup with group-by columns.
  Java sorts each coarser level by the columns of the level below, so it fails with a
  `NoSuchColumnException` unless the sort columns are results of the same aggregation
  under their own names, and then sorts results, not source rows. This server makes the
  case Java makes and refuses the others as not ported. Reproducing Java's failure, or
  sorting the source rows, is the owner's call (`docs/HIERARCHICAL.md`, "Which
  aggregations").
- The four `rollup_*` lines of `oracle/replay-baseline.json` are new lines, all `clean`:
  the pull request needs `oracle-change`.
- `BrowserFlightService` is in the area of task 2.6; the two calls were added here because
  the IDE cannot expand a node without them.
- A snapshot is read under the update graph's shared lock; Java reads without it and
  retries. Every level aggregates the source; Java aggregates the level below (7.8.5).
- Seen while probing and not part of this task: a `DoExchange` subscription whose ticket
  is a scope ticket of something that is not a table is answered `Ticket (scope/<name>)
  is not a subscribable table.` here and `Could not resolve ticket 'ticket': found
  0x<hex> (hex)` by Java.
- Not checked: a view of more rows than the
  harness reads (2 000).
