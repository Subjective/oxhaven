## Scope

`Apply` with update views and format views per node type of a rollup; the Python
recorder's `update_view`, `format_column`, `format_row_where`, `format_column_where`;
`RollupTable.with_update_view`; the added columns in the snapshot schema. A tree's
`Apply` does not read its views, as Java's does not.

## Gate

`cargo test -p oxhaven-engine hierarchical`, `cargo test -p oxhaven-server hierarchical`
with and without `--features python` (`node_view_tests.rs` compares the snapshot schema of
update views and format views with Java's field by field), the script scenarios
`rollup_update_view` and `rollup_formatted` clean in the replay gate.

## Notes

- No contract changed. `HierarchicalError` has a variant `Formula` for a view that does
  not compile.
- Changed under `oracle/` (additive): two scenarios with their recordings and their
  `clean` lines in `oracle/replay-baseline.json`.
- A node's added columns are computed when read, with no listener: a ticking rollup's
  snapshot reads them again each time, as it reads the levels.
- **For the owner's ruling:**
  - Java refuses operations that add columns for nodes that have operations of any kind,
    sorts included (`RollupNodeOperationsRecorder#withOperations`: `Incompatible operation
    recorders; ...`). So `with_update_view` twice, two update views in a row, formats after
    a sort, and update views and formats of one node type in one `Apply` fail. Reproduced.
  - Java's `Apply` does not read the update views and format views of a request for a
    tree, whatever they say. Reproduced (it was refused by name before).
  - Java checks the views of `Apply` against the columns of the source, so an update view
    that reads a result of an aggregation is refused though the nodes have it. Reproduced.
- Not built: the tree recorder's formats (`TreeNodeOperationsRecorder#formatColumns`,
  `#formatRowWhere`, `#formatColumnWhere`), refused by name as before; carrying formats and
  update views to the constituent nodes as `#translateAggregatedNodeOperationsForConstituentNodes`
  does (only `Apply`'s sorts call it in Java).
