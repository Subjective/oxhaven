## Scope

In order, each probed on the Java reference before it is written:

1. The tree recorder's formats and filters: `format_column`, `format_row_where`,
   `format_column_where` and `where` of the Python `TreeNodeOperationsRecorder`
   (`TreeNodeOperationsRecorder#formatColumns`, `#formatRowWhere`, `#formatColumnWhere`,
   `#where`), applied with `TreeTable.with_node_operations`; the formatting columns in the
   snapshot schema; a node's rows that a node filter drops, and the expandability of a row
   whose children it drops. `Apply` keeps ignoring a tree's views, as Java's does.
2. Colours as formula values, refused in 4.21: a colour as the value of a column
   (`AK = RED`, `RED.toHex()`, `new Color(..)`), `io.deephaven.engine.util.ColorUtil.RED`,
   `colorRGB(int, boolean)`, with the column type Java sends for a colour column, if the
   object column type of 5.10 can hold it without a contract change.
3. Formats and update views carried to a rollup's constituent nodes as
   `RollupTableImpl#translateAggregatedNodeOperationsForConstituentNodes` allows, only on
   the call paths where Java does it.
